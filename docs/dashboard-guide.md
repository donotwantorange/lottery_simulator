# 网页页面指南

本文说明当前 React＋Django 网页的实际界面。前端路由包括登录，以及“新建实验”“角色池”“实验结果”“历史记录”和管理员五个工作页面。浏览器对同源 `/api` 发请求；CSRF、身份和对象权限由服务器校验。本地双账号浏览器实际观察见[验收记录](changes/2026-09-29-user-pool-browser-acceptance.md)；公网和生产部署未验。

## 登录与主导航

访问 `/accounts/login/` 输入管理员创建的用户名和密码。系统不开放注册。管理员设置的初始密码在首次登录后必须修改，修改成功会退出当前会话并要求重新登录。主界面侧栏按权限显示页面链接、用户名和角色，提供修改密码及退出登录操作。账号被停用、密码或角色变化后，服务端会拒绝旧会话。

## 角色池

“角色池”列表可以筛选全部可见、公共池、我的私有池、他人公开池；管理员还可看全部私有池。表格列出池名、类型/可见性、所有者、最初作者和修订号。选择自有池或管理员可管理的池进入编辑；其他可见池以只读方式查看并可复制。

点击“新建角色池”建立隐藏私有池；管理员可选择公共池。编辑字段包括：

- 池名、池类型、私有池可见性（仅自己/对登录用户公开）、最初作者。已有池不能原地更改类型或最初作者；转类型需复制。署名是来源说明，不授予权限。
- 4、5、6星显示名称。默认分别是“四星、五星、六星”，历史快照保留运行时名称；记录内部稀有度编号仍为4/5/6。
- UP占六星概率、五星基础概率、五星硬保底抽次及启用五星保底开关。
- 六星角色表：名称、UP、限定、UP权重，可添加/移除。勾选UP会同时设为限定并补默认权重1；取消UP会清空UP权重。普通非UP角色不填写UP权重。
- 四星和五星角色名单：名称及抽取权重，可添加/移除。
- 附赠奖励：奖励名及四星/五星/六星数值，可添加/移除。

概率和奖励等小数在输入框失焦时提交到本地草稿，点击“创建角色池”或“保存修改”才写入服务器。服务器还会校验名称唯一、权重、概率与规则约束。保存携带当前修订号；发生冲突时重新选择/加载池并核对后再改。

“导出JSON”保存当前池文档；“导入池JSON”会导入成当前用户的隐藏私有池，不会按文件中的权限意图创建公共池。删除池需要确认，并会使引用该池的配置失去池关联；已完成历史仍保留快照。可填写新名称和类型“复制为新池”，复制产生新ID并保留最初作者；普通用户不能复制为公共池。

## 新建实验与配置

“实验配置”区域提供已保存配置选择、实验名称、保存/保存修改、另存为新配置、导入和导出JSON。只有明确点击保存才写入配置。导入文件后，页面先按池ID或名称解析角色池；同名多个候选需要选择，没有匹配时需选择当前可用池，再点击“确认导入并保存”。

“本次模拟”选择角色池并展示绑定规则、最初作者、修订号和名单摘要。实验不能覆盖池的规则或角色。普通用户只管理自己的实验配置；管理员编辑他人配置时，绑定池必须是配置所有者可使用的池，也可另外选择管理员本人本次运行使用的池。

实验参数如下：

| 字段 | 含义 |
|---|---|
| 每轮主池抽数 | 每一轮新增的主池抽数，必须为正整数 |
| 实验轮数 | 独立重复轮数，必须为正整数 |
| 假设主池已累计多少抽仍未出6星 | 初始化六星未出进度，也表示已经累计的主池抽数；由规则限定范围 |
| 假设已连续多少抽未出5星或以上 | 初始化五星保底进度；按池的五星保底开关和硬保底校验 |
| 随机种子 | 可留空；使用十进制整数文本传输，避免大整数精度丢失 |
| 保存每抽明细（Trace） | 默认关闭；开启后逐抽记录含赠送抽也保存 |

本次模拟初始值为每轮主抽100、轮数1000、两种保底进度0、空种子、关闭Trace。普通用户限额默认主抽/轮≤1000万、轮数≤100万、两者乘积≤1亿；Trace记录默认≤100万，单次下载默认≤1万。后两项可通过 `LOTTERY_MAX_TRACE_RECORDS`、`LOTTERY_MAX_TRACE_DOWNLOAD_RECORDS` 配置；管理员免除这些业务数量限额，但仍受类型、规则、授权、存储和机器资源限制。最终由服务端校验。

点击“开始模拟”才提交任务，成功后跳到结果页。网络超时等导致提交结果不确定时，系统不会自动重发；按时间、池和参数人工核对“本人最近任务”。列表为空也不能证明原请求未被接受。

## 实验结果：状态与概览

结果页顶部“本人最近任务”可选择任务。运行中页面每2秒查询状态，页面隐藏时降低频率；可点击“停止任务”。停止是取消请求，不是删除按钮；已提交的历史不会被停止操作删除。状态中有全局进度和阶段进度，保存失败会显示持久化错误，不能当作已写入历史。

完成后可切换四种视图：

1. **实验概览**：模拟六星均值、理论六星期望、相对误差；每轮及全实验的主池、赠送和总抽数；规则/版本、轮数、种子、耗时、池快照及Trace条数。相对误差显示绝对百分比；理论期望为零时显示不可用。“下载汇总 JSON”下载汇总，不含逐抽记录。
2. **分类统计**：先选来源（主池、赠送、总计）和分类，再看图及表格。五类为星级、六星构成（UP限定/其他限定/常驻）、六星具体角色、奖励和保底。横向对照展示模拟均值与理论期望；奖励未配置时显示空状态。分类统计中的来源筛选仅作用于当前图表。
3. **按抽次分析**：仅Trace实验可用。选主池或赠送、计数或比例、轮次起止、来源位置起止（最多1000个连续位置）及4/5/6星显示名称，可多选。横轴位置是该来源内第几抽；分母是所选轮次在该位置的实际观察数。取消全部稀有度会显示提示，不发起模拟。
4. **逐抽明细**：Trace实验可按第1轮、指定轮次、轮次范围或全部轮次筛选；还可选主池/赠送来源、稀有度、角色、来源抽次区间。角色筛选仅在选定稀有度后出现，可选“未配置角色名单”。每页50/100/200条；基础列/完整列切换，条件概率仍按0～1数值显示。筛选会重置页码。

逐抽基础列含轮次、轮内抽次、来源、来源内序号、稀有度、角色、主池累计抽数、UP和限定标记。完整列增加四/五星/六星概率、来源池与主池抽前/后两种保底进度、五星保底/六星硬保底触发、赠送事件及每项奖励。

“在新标签页下载 Trace JSONL”是历史运行的原生表单下载，按当前筛选下载所有匹配项而不是当前页；需要浏览器允许弹出下载标签页。首行是包含池快照和筛选条件的元数据，其后每行一条记录。稀有度显示名不会改动 JSON 中稳定的4/5/6编号。运行尚未保存为历史时可分页查看，但下载需等历史运行ID可用。未开启Trace无法事后生成逐抽记录。

## 历史记录

“历史记录”按创建时间倒序分页，每页20条，可按规则名称和是否含Trace筛选。列表显示时间、池快照名称、规则、主抽数、轮数和Trace条数。点“查看”后显示保存时池修订号、快照和相同四种结果视图。

“按当前角色池重跑”会读取当前池并和保存快照比较；确认提示中说明池修订、名称或稀有度名称差异。确认后再检查修订号，使用当前池与历史参数提交新任务。它不是用历史快照直接启动，也不会覆盖原历史。请求结果不确定时不自动重发，可查询本人近期任务。

“删除历史”后需在确认区再次确认；删除历史及Trace不可撤销。普通用户只能操作自己的历史，管理员可管理全部。

## 管理员

管理员页有账号管理、实验配置管理和任务管理三个区域。可创建账号、编辑用户名/角色/启用状态、重置密码、解除登录失败锁定和删除账号。重置密码要求首次登录改密；用户名、角色、启用状态或密码变化会撤销旧会话。不能删除自己，也不能移除最后一个可用管理员。删除账号先展示私有池（包括公开私有池）、配置、历史、任务目录和导出文件范围，勾选已核对后再确认；删除任务必须确认停止，清理失败保留可重试状态。系统公共池和他人历史不在删除范围。

实验配置管理列出所有者、池和参数，可进入配置编辑页或二次确认删除。任务管理列出接受时间、用户、池、参数规模和状态，管理员可向活动任务发送停止请求。直接访问管理API仍由服务端鉴权。

## 验收状态

代码已有对应页面及接口。本地浏览器记录覆盖了登录会话、刷新/历史深链接、第二账号隔离、图表、筛选和带CSRF的原生下载请求；内置浏览器没有暴露下载附件保存事件，所以未核对操作系统保存位置。该观察不能替代公网HTTPS、真实反向代理和生产部署验收。

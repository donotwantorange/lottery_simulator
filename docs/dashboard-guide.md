# 网页页面详细说明

本文对应规则1版本 `2.0` 的本地网页界面。安装、启动、CLI、备份及常见环境问题见[本地使用手册](local-usage.md)。

界面由左侧参数设置、右侧六个结果标签页，以及下方历史记录组成；六个标签页不是六个独立网页。

## 1. 左侧：设置本次实验

### 基本参数

| 参数 | 含义 |
|---|---|
| 规则 | 当前使用 `rule1` |
| 主池抽数 | 每轮新增的主池抽数，不包含赠送抽或假设的历史抽数 |
| 实验轮数 | 将相同条件独立重复多少轮，用于估计概率和平均收益 |
| 假设主池已累计多少抽仍未出6星 | 同时初始化六星保底进度和历史主池累计抽数，范围0～79 |
| 随机种子 | 固定随机过程，便于同配置、同版本复现；留空自动生成 |
| Trace | 默认关闭；开启后保存逐抽记录，只支持实验轮数为1 |

例如主池抽数100、实验轮数10000、初始进度0，表示独立进行10000轮实验，每轮从初始状态开始抽100次主池。不是连续抽一百万次并跨轮接续保底。符合条件时，每轮另有赠送10抽。

网页主池抽数上限1000万，实验轮数上限100万，两者乘积不超过1亿；网页 Trace 主池抽数上限10万。CLI和核心不增加这个Trace上限。开始前会统一校验。

### 初始进度与首次赠送

- 填0：从头开始，完成第30次主池抽取后触发赠送。
- 填29：本轮再主抽一次，就触发赠送。
- 填60：假设历史已主抽60次且连续未出六星，赠送已领取；下一抽是六星保底周期的第61抽。

历史抽数只初始化状态，不补算历史角色或奖励。主池累计抽数不会因六星而归零；六星保底进度会归零。

### 高级设置：五星初始进度

“假设主池已连续多少抽未出5星及以上”设置五星保底初始进度。

默认硬保底10抽时，填0表示从头累计，填9表示下一抽至少五星。得到五星只重置五星保底，得到六星同时重置两种保底。开启时初始值必须小于五星硬保底；关闭主池五星保底时初始值只能为0。

### 奖池与奖励设置

**UP占比**是已经抽到六星时属于UP的合计概率，不是单抽直接获得UP的概率。普通抽六星概率0.8%、UP占比50%时，该抽UP六星概率为 `0.8% × 50% = 0.4%`。输入0.5表示50%；合法值大于0且不超过1。

**五星概率**默认8%，**启用五星保底**可开关主池五星保底，**五星硬保底**默认10。普通抽四星概率为 `1 − 六星概率 − 五星概率`，默认前期91.2%，随六星概率提升而下降；到五星保底位置，保留六星概率，剩余概率归五星。

六星角色表可增删行；四星、五星角色名单不在网页表格编辑，使用配置 JSON 编辑：

| 列 | 作用 |
|---|---|
| 角色名称 | 用于具体角色统计，非空且唯一 |
| 是否UP | 决定是否参与UP份额分配 |
| 是否限定 | 决定是否属于限定，UP必须同时是限定 |
| UP权重 | 仅UP使用，必须有限且严格为正，可为小数 |

两名UP权重1、3，UP合计50%时，两者在所有六星中的占比分别为12.5%、37.5%。所有非UP平分剩余50%；非UP权重应留空，JSON为 `null`。至少有一个UP；UP占比小于1时必须有非UP，全部角色为UP时占比只能为1。

奖励表的“四星／五星／六星”列表示该星级单抽结算的奖励量。例如奖励A填1、5、25，分别表示四星获得1、五星5、六星25单位。奖励名称非空且唯一，数值有限且非负，可以删除全部奖励。

“附赠奖励”与“赠送10抽”是不同机制；每抽可以同时结算多种附赠奖励。

- 导出配置JSON：保存当前奖池设置，不是模拟结果。
- 导入配置JSON：恢复一套奖池设置。
- 恢复默认配置：恢复默认角色、概率、五星保底和奖励。

配置 JSON 必须带 `"format_version": 1`，并可填写 `four_star_characters`、`five_star_characters` 名单；编辑后用 `PoolConfig.from_dict` 校验再导入。批量运行的角色图和角色统计仍只针对六星，四星/五星角色名只会出现在单抽结果和 Trace 中。

编辑单元格后按Enter确认，再开始模拟。无效配置会有中文提示，修正后才能运行。改参数不会自动重新模拟，必须点击“开始模拟”；重新运行前右侧仍是上次结果。任务开始后配置已固定，继续编辑不改变正在运行的实验。

### 运行与停止

开始后显示进度、已用时间和“停止模拟”。固定随机种子、完整配置快照、相同参数、相同 `rule_version`（规则版本）、`sampling_version` 以及 Python 实现/版本时结果可复现；只要任一项变化，就不要把输出当作同一实验。停止或失败的实验不保存为完整历史。正常完成后显示结果；如提示“历史保存失败”，不要认为该次结果已经入库，可先下载结果JSON。

## 2. 结果上方：数据来源

| 来源 | 统计范围 |
|---|---|
| 主池 | 本次新增主池抽取 |
| 赠送 | 首次累计30主抽触发的独立10抽 |
| 总计 | 主池和赠送合并 |

来源选择控制星级、六星构成、具体角色、奖励、保底统计图表。

总览顶部指标同时列出三种来源，不会全部随切换改变；概率折线图始终是主池规则曲线；Trace展示完整逐抽记录，不按来源筛掉行。总览下方的至少一个六星概率是合并来源口径，不随来源切换。

## 3. 总览：整体结果

### 抽数指标

- 主池抽数：每轮新增主抽数量。
- 赠送抽数：每轮新增赠送数量。
- 总抽数：上述两者之和。
- 初始主池累计抽数：假设的历史累计主抽数。
- 结束主池累计抽数：历史累计数加本轮新增主抽，不含赠送。

例：初始29、主抽1次，主池抽数1、赠送抽数10、总抽数11、初始累计29、结束累计30。累计主抽数与当前保底进度不是同一指标。

### 模拟均值、理论期望和误差

模拟六星均值是每轮平均得到的六星数量。例如1000轮共1500个六星，均值为1.5，并不是某轮得到半个角色。

理论期望按规则、配置、初始状态和有限模拟长度计算，不依赖随机抽样。顶部分别显示主池、赠送和总计的模拟值、理论值。

顶部绝对误差比较总六星模拟均值与总理论期望，相对误差为绝对误差除以总理论期望；理论期望为0时相对误差不可用。增加实验轮数通常减少随机波动，但不保证每次增加都让误差下降。随机种子和耗时用于复现与了解运行规模。

### 主池六星概率折线图

横轴是从零保底进度开始、连续未出六星时的抽次，最多80，不是累计主池抽数，也不是本轮实际逐抽结果。

- 条件六星概率：前面都没出六星的条件下，这一抽出六星的概率。
- 首次六星累计概率：从第1抽开始，到该位置为止已经出过至少一次六星的概率。

第1～65抽条件概率0.8%，第66抽5.8%，随后每抽增加5个百分点，第79抽70.8%，第80抽100%。第66抽条件概率5.8%不等于前66抽累计命中概率5.8%。

这是一条完整规则参考曲线。主抽填1000不会延长到1000；初始进度60也不会裁成61～80。出六星后实际保底进度重置，从第1抽重新开始。展开“查看主池六星概率数值”还能看各位置的首次命中概率等数值。

### 星级柱状图与下方信息

星级柱状图比较四、五、六星的每轮模拟均值和理论期望，随来源切换。

- 至少一个六星概率：各轮中主池或赠送至少得到一个六星的比例。
- 已完成周期平均间隔：模拟中已完成的主池六星周期平均间隔。
- 完整周期理论平均间隔：从零进度开始，理论上等到主池六星所需的平均抽数。

有限实验可能留有未完成周期，后两者不一定相同。赠送六星不插入主池周期来计算统一间隔。

## 4. 六星构成：六星类别

| 类别 | 包含什么 |
|---|---|
| UP限定 | 所有UP六星 |
| 其他限定 | 限定但不是UP的六星 |
| 常驻 | 非UP且非限定的六星 |

三类互不重叠，柱状图比较每轮模拟均值和理论期望。限定六星总量为“UP限定＋其他限定”。

默认9名六星中有1名UP、另外2名限定、6名常驻；UP占50%，其余8名各6.25%，所以六星内部三类份额分别为50%、12.5%、37.5%。这些不是单抽直接获得对应类别的概率。

## 5. 具体角色：每名六星的结果

柱状图按角色比较模拟均值和理论期望。展开“查看具体角色数值”可查看：

| 字段 | 含义 |
|---|---|
| 类型 | UP限定、其他限定或常驻 |
| 模拟均值 | 每轮平均得到该角色多少次 |
| 理论期望 | 每轮理论应得到多少次 |
| 六星内实际占比 | 该角色数量占所选来源全部模拟六星的比例 |
| 六星内理论占比 | 配置规定的六星内部份额 |
| 占比误差 | 实际占比减理论占比，正为偏高，负为偏低 |

选定来源没有六星时，实际占比和占比误差为空，不能解释为角色概率为0。当前只保留具体六星角色统计，四星、五星不区分具体角色。

## 6. 附赠奖励：收益均值与分布

第一张图按奖励名称比较每轮模拟奖励总量均值和理论期望，是整轮收益，不是单抽奖励。

“奖励分布”下拉框选定一种奖励后，第二张图：

- 横轴：一轮获得的该奖励总量。
- 纵轴：得到该总量的实验轮数。

例如奖励A总量150的柱子高度80，表示80轮各获得150单位奖励A。展开数值表可看该频数占实验轮数的比例。频数不是单抽概率。

均值回答平均收益，分布回答实际收益可能落在哪里。单轮实验的分布信息有限。没有配置奖励时显示“当前配置没有附赠奖励”。两张图均随来源切换。

## 7. 保底统计：到达保底位置的次数

比较每轮五星保底、六星硬保底的模拟触发次数均值与理论期望。

五星保底触发表示到达至少五星的位置，不保证结果恰好五星，该抽仍可能是六星。六星硬保底是到第80抽，必出六星；第66～79抽概率提升不算此图的六星硬保底。

来源区别：主池使用当前配置的五星保底；赠送池独立从零状态开始、固定六星0.8%、五星保底10抽；总计合并触发次数。关闭主池五星保底不关闭赠送池五星保底。赠送不会推进或重置主池保底，也不递归触发赠送。

## 8. Trace：逐抽检查

运行前需主动开启 Trace，且实验轮数必须为1；默认关闭。JSON记录保持嵌套结构：`draw_result.outcome`（星级、角色、UP/限定、奖励、保底触发）、`draw_result.probabilities`（四/五/六星概率）、`draw_result.state_before/state_after`（来源池状态），以及记录级 `main_state_before/main_state_after`（主池状态）。网页只读展开为以下中文列：

| 中文列 | 数据路径 |
|---|---|
| 总体抽取序号、来源、来源内序号、主池累计抽数、赠送事件 | `draw_index`、`source`、`source_index`、`main_draws_completed`、`bonus_event` |
| 星级、角色、是否UP、是否限定 | `draw_result.outcome.rarity/character_name/is_up/is_limited` |
| 四星概率、五星概率、六星概率 | `draw_result.probabilities.four_star/five_star/six_star` |
| 来源池与主池抽前/后未出六星、未出五星及以上 | `draw_result.state_before/state_after`、`main_state_before/main_state_after` |
| 五星保底、六星硬保底、各奖励 | `draw_result.outcome.five_star_pity_triggered`、`six_star_hard_pity_triggered`、`rewards` |

概率在下载 JSON 中保持 `0..1`，表格按百分比显示；未配置角色时显示“未配置角色名单”。没有开启 Trace 时明确显示未保存逐抽记录，不能事后从历史补出。

适合检查规则边界：初始主池累计29，主抽1次，随后应插入10次赠送；赠送期间主池累计数保持30，主池保底状态不被赠送结果改变。

没有开启Trace时显示“本次运行未保存逐抽记录”。历史不能事后补出记录，需重新运行。来源选择不会过滤这张完整逐抽表。

## 9. 历史记录：保存、复用与比较

位于当前结果下方。可按规则、是否含Trace、开始和结束日期筛选，日期按UTC；每页最多20条，按创建时间倒序，改变筛选后可把页码设为1。

“选择历史运行”选1条查看详情，选2条并排比较。规则、版本或快照结构不同会提示口径不同，仅并排展示，不叠加曲线。

历史详情同样有六个结果标签页，但未保存概率曲线，因此不会重画折线图，只展示保存的指标和分布。“配置摘要”展示历史运行的奖池快照与初始五星进度，不是当前侧栏的新配置。

“复用参数”把当次参数与配置恢复到侧栏，不立即运行；可继续修改，再点击开始。“删除历史”先进入确认，随后“确认删除”才执行，无法撤销，逐抽记录也一起删除；“取消删除”保留数据。

正常完成且历史保存成功的网页模拟进入数据库。非Trace保存参数、配置、汇总与统计分布；Trace另外保存逐抽记录。取消或失败的实验不保存为完整历史，CLI不会自动写网页历史库。

“下载结果JSON”下载模拟结果；侧栏“导出配置JSON”只下载奖池配置。结果JSON不是数据库备份。

## 10. 推荐阅读与操作顺序

先设置奖池和初始状态，用小规模单轮Trace检查赠送与保底边界；再关闭Trace、增加实验轮数，按总览、六星构成、具体角色、附赠奖励、保底统计检查批量结果；最后保存配置或下载结果，在历史中复用与比较。

环境、网页上限、数据目录和备份恢复见[本地使用手册](local-usage.md)。设计与修改过程见[修改记录](changes/README.md)。

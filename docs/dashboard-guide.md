# 网页页面详细说明

本文对应规则1版本 `2.0` 的本地网页界面。安装、启动、CLI、备份及常见环境问题见[本地使用手册](local-usage.md)。

✅ 本文所述多轮Trace、三页面和四种结果视图已于2026-09-22本地合并到`master`，合并后的主目录全套385项测试通过；当前操作入口是项目主目录。详见[多轮Trace实施记录](changes/2026-09-20-multi-trial-trace-ui.md)和[本地合并记录](changes/2026-09-22-multi-trial-trace-ui-local-merge.md)。⚠️真实浏览器视觉、服务器部署和实际旧数据切换仍未完成。

界面固定为三个页面：“新建实验”“实验结果”“历史记录”。“新建实验”负责参数和奖池配置，“实验结果”提供四种视图，“历史记录”负责筛选、查看、复用、比较和删除；它们不是三个独立服务。

## 1. 新建实验：设置本次实验

左侧“导航”切换三个页面；运行中任务的阶段、进度、耗时和“停止模拟”也显示在侧栏。参数、奖池配置、启动摘要和“开始模拟”均在“新建实验”的主区域，不在侧栏。开始后自动切到“实验结果”，顶部“结果视图”切换四种结果。页面间切换保留当前会话草稿；长期保留奖池设置请导出配置 JSON，不要依赖浏览器刷新保存草稿。

### 基本参数

| 参数 | 含义 |
|---|---|
| 规则 | 当前使用 `rule1` |
| 主池抽数 | 每轮新增的主池抽数，不包含赠送抽或假设的历史抽数 |
| 实验轮数 | 将相同条件独立重复多少轮，用于估计概率和平均收益 |
| 假设主池已累计多少抽仍未出6星 | 同时初始化六星保底进度和历史主池累计抽数，范围0～79 |
| 随机种子 | 固定随机过程，便于同配置、同版本复现；留空自动生成 |
| Trace | 默认关闭；开启后按轮次保存逐抽记录，赠送抽也计入记录数 |

例如主池抽数100、实验轮数10000、初始进度0，表示独立进行10000轮实验，每轮从初始状态开始抽100次主池。不是连续抽一百万次并跨轮接续保底。符合条件时，每轮另有赠送10抽。

网页主池抽数上限1000万，实验轮数上限100万，两者乘积不超过1亿；Trace 默认总实际记录上限1,000,000，单次明细下载上限10,000。记录数按每轮主抽加赠送抽计算，可用 `LOTTERY_MAX_TRACE_RECORDS` 和 `LOTTERY_MAX_TRACE_DOWNLOAD_RECORDS` 覆盖；必须重启网页进程后才生效。CLI Trace 记录保存在内存中，完整大实验请使用网页落库后本地导出。开始前和 worker 冷启动时会校验网页上限。

### 初始进度与首次赠送

- 填0：从头开始，完成第30次主池抽取后触发赠送。
- 填29：本轮再主抽一次，就触发赠送。
- 填60：假设历史已主抽60次且连续未出六星，赠送已领取；下一抽是六星保底周期的第61抽。

历史抽数只初始化状态，不补算历史角色或奖励。主池累计抽数不会因六星而归零；六星保底进度会归零。

### 高级设置：五星初始进度

“假设主池已连续多少抽未出5星及以上”设置五星保底初始进度。

默认硬保底10抽时，填0表示从头累计，填9表示下一抽至少五星。得到五星只重置五星保底，得到六星同时重置两种保底。开启时初始值必须小于五星硬保底；关闭主池五星保底时初始值只能为0。

### 奖池与奖励设置

**UP占比**是已经抽到六星时属于UP的合计概率，不是单抽直接获得UP的概率。普通抽六星概率0.8%、UP占比50%时，该抽UP六星概率为 `0.8% × 50% = 0.4%`。输入0.5表示50%；合法值大于0且不超过1。

**五星概率**默认8%，**启用五星保底**可开关主池五星保底，**五星硬保底**默认10。普通抽四星概率为 `1 − 六星概率 − 五星概率`，默认前期91.2%，随六星概率提升而下降；到五星保底位置，保留六星概率，剩余概率归五星。

六星角色表可增删行；四星、五星角色名单不在网页表格编辑，使用配置 JSON 编辑：

| 列 | 作用 |
|---|---|
| 角色名称 | 用于具体角色统计，非空且唯一 |
| 是否UP | 决定是否参与UP份额分配 |
| 是否限定 | 决定是否属于限定，UP必须同时是限定 |
| UP权重 | 仅UP使用，必须有限且严格为正，可为小数 |

两名UP权重1、3，UP合计50%时，两者在所有六星中的占比分别为12.5%、37.5%。所有非UP平分剩余50%；非UP权重应留空，JSON为 `null`。至少有一个UP；UP占比小于1时必须有非UP，全部角色为UP时占比只能为1。

奖励表的“四星／五星／六星”列表示该星级单抽结算的奖励量。例如奖励A填1、5、25，分别表示四星获得1、五星5、六星25单位。奖励名称非空且唯一，数值有限且非负，可以删除全部奖励。

“附赠奖励”与“赠送10抽”是不同机制；每抽可以同时结算多种附赠奖励。

- 导出配置JSON：保存当前奖池设置，不是模拟结果。
- 导入配置JSON：恢复一套奖池设置。
- 恢复默认配置：恢复默认角色、概率、五星保底和奖励。

配置 JSON 必须带 `"format_version": 1`，并可填写 `four_star_characters`、`five_star_characters` 名单；编辑后用 `PoolConfig.from_dict` 校验再导入。批量运行的角色图和角色统计仍只针对六星，四星/五星角色名只会出现在单抽结果和 Trace 中。

编辑单元格后按Enter确认，再开始模拟。无效配置会有中文提示，修正后才能运行。改参数不会自动重新模拟，必须点击“开始模拟”；“实验结果”仍指向此前选择的结果，直到启动新任务或选择另一条历史。任务开始后配置已固定，继续编辑不改变正在运行的实验。

“启动预览”列出每轮主抽、赠送、总抽数，以及全实验抽数和预计 Trace 记录数。检查后点击“开始模拟”，页面会跳转到“实验结果”；已有任务运行时不能启动第二个任务。

### 运行与停止

开始后侧栏显示当前阶段、进度、已用时间和“停止模拟”。阶段标签依次可能为“模拟运行中”“计算理论统计”“校验明细”“写入明细/保存历史”“提交历史”。主抽计数达到100%只表示主抽完成，之后仍可能进行理论计算、明细校验和保存；理论阶段总量未知。校验/写入阶段的计数达到100%也只表示该阶段工作项已处理，并不表示历史事务已经提交，最终应看“模拟已完成”和保存状态。停止请求可能需要等待当前计算阶段响应；提交历史前成功取消会清除未完成的结果和Trace文件，不能续算或恢复。若提交已完成，停止请求会保留历史。固定随机种子、完整配置快照、相同参数、相同 `rule_version`（规则版本）、`sampling_version` 以及 Python 实现/版本时结果可复现；只要任一项变化，就不要把输出当作同一实验。停止或失败的实验不保存为完整历史。正常完成后显示结果；如提示“历史保存失败”，不要认为该次结果已经入库：计算结果仍完整保留在当前结果页，未开启 Trace 时可查看/下载完整汇总；开启 Trace 时，`jobs_v4/<job_id>/` 保留完整 `trace.sqlite3` 和 `result.json`，当前结果页仍可分页查看、筛选和导出明细。任务目录文件不在历史备份中。

## 2. 实验结果：视图与数据来源

结果页上方显示当前任务或历史记录的 ID、Trace 开关和记录数。“参数与配置快照”展示该次实际参数，而不是当前草稿；“复用参数”将快照恢复到“新建实验”，不自动运行。“结果视图”一次选择实验概览、分类统计、按抽次分析或逐抽明细之一。

| 来源 | 统计范围 |
|---|---|
| 主池 | 本次新增主池抽取 |
| 赠送 | 首次累计30主抽触发的独立10抽 |
| 总计 | 主池和赠送合并 |

“数据来源”选项位于“分类统计”，控制其中星级、六星构成、六星具体角色、奖励、保底图表。

实验概览没有来源切换，六星均值及理论期望使用主池与赠送的总计口径。“按抽次分析”仅在主池、赠送之间选择；逐抽明细另有自己的来源筛选。三者筛选不是联动的。

## 3. 实验概览：整体结果

### 抽数指标

- 每轮主池抽数：每轮新增主抽数量。
- 每轮赠送抽数：每轮新增赠送数量。
- 每轮总抽数：上述两者之和。
- 实验总主池抽数、实验总赠送抽数、实验总抽数：对应的每轮数量乘以实验轮数。

下方表格固定为“每轮”和“全实验”两行，分别汇总上述抽数；不是逐轮抽取结果表。初始累计主抽可在参数快照中查看；初始/结束累计主抽字段 `initial_main_draws`、`final_main_draws` 保留在汇总 JSON 中，不是当前顶部指标。

例：初始29、主抽1次，主池抽数1、赠送抽数10、总抽数11、初始累计29、结束累计30。累计主抽数与当前保底进度不是同一指标。

### 模拟均值、理论期望和误差

模拟六星均值是每轮平均得到的六星数量。例如1000轮共1500个六星，均值为1.5，并不是某轮得到半个角色。

理论期望按规则、配置、初始状态和有限模拟长度计算，不依赖随机抽样。概览显示总计六星模拟均值和理论期望，顶部数值保留4位小数，极小非零值使用科学计数法；下载汇总 JSON 保留原始数值。分来源的星级比较在“分类统计”中查看。

概览的“相对误差”显示 `|模拟均值 − 理论期望| / 理论期望`，理论期望为0时不可用。汇总 JSON 的 `mean_count_error` 和 `mean_count_relative_error` 保留正负方向，概览没有单独的绝对误差指标。增加实验轮数通常减少随机波动，但不保证每次增加都让误差下降。下方还显示规则、规则版本、实验轮数、种子和运行耗时。

### 主池六星概率折线图在哪里

这张图位于“新建实验”中的“主池规则预览”，不是实验概览的一部分，使用正在编辑的有效配置。

横轴是从零保底进度开始、连续未出六星时的抽次，最多80，不是累计主池抽数，也不是本轮实际逐抽结果。

- 条件六星概率：前面都没出六星的条件下，这一抽出六星的概率。
- 首次六星累计概率：从第1抽开始，到该位置为止已经出过至少一次六星的概率。

第1～65抽条件概率0.8%，第66抽5.8%，随后每抽增加5个百分点，第79抽70.8%，第80抽100%。第66抽条件概率5.8%不等于前66抽累计命中概率5.8%。

这是一条完整规则参考曲线。主抽填1000不会延长到1000；初始进度60也不会裁成61～80。出六星后实际保底进度重置，从第1抽重新开始。网页没有独立的“查看主池六星概率数值”按钮；完整数值可运行 `.venv/bin/python -m lottery_simulator analyze --format json` 查看，使用自定义配置时还应传入 `--pool-config`。

### 汇总 JSON 中的补充统计

星级柱状图在“分类统计”的“星级”中。以下数据保留在汇总 JSON，当前概览没有单独展示：

- 至少一个六星概率：各轮中主池或赠送至少得到一个六星的比例。
- 已完成周期平均间隔：模拟中已完成的主池六星周期平均间隔。
- 完整周期理论平均间隔：从零进度开始，理论上等到主池六星所需的平均抽数。

有限实验可能留有未完成周期，后两者不一定相同。赠送六星不插入主池周期来计算统一间隔。

## 4. 分类统计：星级、六星构成、角色、奖励和保底

“分类统计”视图通过二级选择框提供以下五种统计，均可切换主池、赠送和总计来源。五类柱状图都并排显示“模拟均值”和“理论期望”，柱上标签通常保留4位小数；会舍入成零的非零小值改用科学计数法，悬停数值和下方数据表保留最多12位有效数字。

### 星级

比较四、五、六星的每轮模拟均值和理论期望，同时直接显示数值表。

### 六星构成：六星类别

| 类别 | 包含什么 |
|---|---|
| UP限定 | 所有UP六星 |
| 其他限定 | 限定但不是UP的六星 |
| 常驻 | 非UP且非限定的六星 |

三类互不重叠，柱状图比较每轮模拟均值和理论期望。限定六星总量为“UP限定＋其他限定”。

默认9名六星中有1名UP、另外2名限定、6名常驻；UP占50%，其余8名各6.25%，所以六星内部三类份额分别为50%、12.5%、37.5%。这些不是单抽直接获得对应类别的概率。

### 具体角色：每名六星的结果

选择“六星具体角色”，柱状图按角色比较模拟均值和理论期望；下方直接显示数值表，无需展开：

| 字段 | 含义 |
|---|---|
| 类型 | UP限定、其他限定或常驻 |
| 模拟均值 | 每轮平均得到该角色多少次 |
| 理论期望 | 每轮理论应得到多少次 |
| 六星内实际占比 | 该角色数量占所选来源全部模拟六星的比例 |
| 六星内理论占比 | 配置规定的六星内部份额 |
| 占比误差 | 实际占比减理论占比，正为偏高，负为偏低 |

选定来源没有六星时，实际占比和占比误差为空，不能解释为角色概率为0。此处仅汇总具体六星角色；配置了四、五星名单时，其具体角色可在 Trace 查看。

### 奖励：收益均值

按奖励名称比较每轮模拟奖励总量均值和理论期望，并直接显示数值表；这是整轮收益，不是单抽奖励。未配置奖励时没有奖励柱状图，表格为空。

当前页面没有“奖励分布”选择框或第二张分布图。分布保留在“下载汇总 JSON”的 `source_distributions.<来源>.reward_totals.<奖励名>` 中：键是每轮奖励总量，值是实验轮数。例如 `"150": 80` 表示80轮各获得150单位奖励，频数除以总轮数得到占比，不是单抽概率。

### 保底统计：到达保底位置的次数

比较每轮五星保底、六星硬保底的模拟触发次数均值与理论期望。

五星保底触发表示到达至少五星的位置，不保证结果恰好五星，该抽仍可能是六星。六星硬保底是到第80抽，必出六星；第66～79抽概率提升不算此图的六星硬保底。

来源区别：主池使用当前配置的五星保底；赠送池独立从零状态开始、固定六星0.8%、五星保底10抽；总计合并触发次数。关闭主池五星保底不关闭赠送池五星保底。赠送不会推进或重置主池保底，也不递归触发赠送。

## 5. 按抽次分析和逐抽明细：Trace

运行前需主动开启 Trace；默认关闭。多轮 Trace 的每条 JSON 记录保持嵌套结构：`draw_result.outcome`（星级、角色、UP/限定、奖励、保底触发）、`draw_result.probabilities`（四/五/六星概率）、`draw_result.state_before/state_after`（来源池状态），以及记录级 `main_state_before/main_state_after`（主池状态）。记录级 `trial_index` 是轮次，`draw_index` 是该轮内主池和赠送合并后的总抽次，`source_index` 是来源内序号；赠送抽包含在 `record_count` 中。网页只读展开为以下中文列：

| 中文列 | 数据路径 |
|---|---|
| 轮次、轮内总抽次、来源、来源内序号、主池累计抽数、赠送事件 | `trial_index`、`draw_index`、`source`、`source_index`、`main_draws_completed`、`bonus_event` |
| 星级、角色、是否UP、是否限定 | `draw_result.outcome.rarity/character_name/is_up/is_limited` |
| 四星概率、五星概率、六星概率 | `draw_result.probabilities.four_star/five_star/six_star` |
| 来源池与主池抽前/后未出六星、未出五星及以上 | `draw_result.state_before/state_after`、`main_state_before/main_state_after` |
| 五星保底、六星硬保底、各奖励 | `draw_result.outcome.five_star_pity_triggered`、`six_star_hard_pity_triggered`、`rewards` |

概率在下载 JSON 和当前完整列的表格中都使用 `0..1` 数值，例如 `0.008` 表示0.8%，不是0.008%。未配置角色时显示“未配置角色名单”。完整列还保留“总体抽取序号”，其值与“轮内总抽次”相同，每轮重新计数，不是跨轮全局序号。没有开启 Trace 时明确显示未保存逐抽记录，不能事后从历史补出。

适合检查规则边界：初始主池累计29，主抽1次，随后应插入10次赠送；赠送期间主池累计数保持30，主池保底状态不被赠送结果改变。

### 按抽次分析

选择“位置来源”（主池或赠送）、“位置轮次起/止”、“位置起/止”和“统计口径”（计数或比例）。默认显示从起点起最多200个位置，单次最多1000个连续位置，可以改变起点查看后续区间。

横轴是各轮该来源的第几抽，即 `source_index`，不是保底进度，也不包含假设的历史主抽数。主抽1000次时可以查看第81抽及以后；主池与赠送不能合并成一条来源曲线。计数是所选轮次在该位置得到四、五、六星的轮数；比例的分母是该位置的实际观察轮数。明细的星级、角色筛选不会改变这张图的分母。

### 逐抽明细与下载

1. “轮次”默认第1轮；多轮实验还可选择指定轮次、轮次范围或全部轮次。
2. 按来源、星级、角色筛选，必要时勾选“限制来源抽次区间”。查看无名单的结果时，先选择具体星级，再选“未配置角色名单”。
3. “每页条数”可选50、100、200，默认100，用“上一页/下一页”翻页。“基础列”显示轮次、轮内总抽次、来源、来源内序号、星级、角色、累计主抽及UP/限定标记；切到“完整列”才显示概率、保底前后状态、奖励等全部字段。
4. 点击“准备下载”，再点击“下载明细 JSONL”。下载的是全部匹配记录，不只是当前页；默认超过10,000条需缩小筛选，不会截断。改变筛选或切换结果后需重新准备下载。

JSONL首行是元数据，含运行快照、筛选条件和匹配记录数，随后每行一条嵌套原始记录；不是中文表格的导出。超过网页下载上限的已入库Trace，可以使用本地手册的 `export-trace` 命令完整导出。未开启Trace不能事后补出记录，需重新模拟。

## 6. 历史记录：保存、复用与比较

从侧栏导航进入独立的“历史记录”页面。可按规则、是否含Trace、开始和结束日期筛选，日期按UTC；每页最多20条，按创建时间倒序，改变筛选后如需从头查看，请手动把页码设为1。

在“选择历史运行”中选中一条记录，再点操作栏“查看结果”，即可进入“实验结果”的四种视图；选中两条可并排比较，不会全量加载Trace。规则、版本或快照结构不同会提示口径不同，仅并排展示，不叠加曲线。

“配置摘要”展示历史运行的奖池快照与初始五星进度，不是当前“新建实验”的草稿。历史结果不展示新建页面的规则预览曲线。

“复用参数”把当次参数与配置恢复到“新建实验”并跳转，不立即运行；可继续修改，再点击“开始模拟”。“删除历史”先进入确认，随后“确认删除”才执行，无法撤销，逐抽记录也一起删除；“取消删除”保留数据。删除后不能从该任务结果页面恢复已删除的历史。

正常完成且历史保存成功的网页模拟进入数据库。非Trace保存参数、配置、汇总与统计分布；Trace另外保存逐抽记录。取消或失败的实验不保存为完整历史，CLI不会自动写网页历史库。历史保存失败时，Trace 暂存仅供当前结果分页/导出，非Trace仅保留汇总结果文件；两者都不进入历史备份。

“下载汇总 JSON”仅下载参数、配置和汇总统计，不含逐抽记录；“下载明细 JSONL”位于逐抽明细，导出筛选后的原始记录；“新建实验”的“导出配置 JSON”只下载奖池配置。三者都不是数据库备份。

## 7. 推荐阅读与操作顺序

先设置奖池和初始状态，用小规模多轮 Trace 检查轮次、轮内抽次、赠送与保底边界；再关闭 Trace、增加实验轮数，按实验概览和分类统计检查批量结果；需要逐抽数据时在按抽次分析、逐抽明细中筛选或导出，最后在历史中复用与比较。

环境、网页上限、数据目录和备份恢复见[本地使用手册](local-usage.md)。设计与修改过程见[修改记录](changes/README.md)。

# 网页页面指南

本指南说明登录后的规则、角色池、实验和结果页。安装与版本切换见[部署指南](deployment.md)；原本地使用手册保持独立，见[本地使用手册](local-usage.md)。

## 对象关系

```text
独立规则（概率、保底、赠送机制）
    ↑ 一个池绑定一条规则；多个池可共用
角色池（角色、权重、UP组、奖励及规则目标绑定）
    ↑ 实验配置引用池
实验配置（抽数、轮数、种子、Trace、初始上下文）
    ↓ 接受任务时冻结配置
运行与历史（汇总；Trace开启时另存过程事件）
```

规则/池/实验保存在网页数据库；`configs/`里的规则、池和实验 JSON 是示例及 CLI 输入，不会与数据库自动同步。规则或池修改只影响之后接受的任务，历史按原快照展示。保存实验配置不会自动运行；开始模拟也不要求先保存配置。

## 规则

在“规则”页创建、编辑、复制、导入、导出或删除规则。公共规则由管理员管理；私有规则由创建者管理，可设为公开供其他登录用户查看、使用和复制。公开不授予编辑权。已被池引用的规则不能删除；稀有度数量或顺序等结构变化，在被引用时通过复制规则完成。普通参数修改会校验全部引用池，成功后修订号递增；池在下一次运行使用新规则，已接受任务和历史不变。

规则由稳定稀有度 ID、显示名称和 rank 定义档位；档位数量不固定，也不依赖名称或数字外观。基础概率按各档填写，合计必须为100%。每档可独立启用软保底（起点、每抽增加百分点）和硬保底（抽数）；关闭时相关字段不执行。软保底增量从较低档按低到高扣减，已确定的高档概率不会被低档保底反向扣减。硬保底表示“本档或更高”，多个同时到达时采用最高档下限。

编辑器中的稀有度顺序从上到下由低到高；顺序用于保底的高低比较，基础概率仍由各档单独填写。软保底增幅以百分点计算，例如0.8%增加5个百分点为5.8%。大保底只看主池是否抽中目标：连续未中达到阈值时主抽必得目标；命中后可关闭本轮或清零计数继续循环，赠送抽和周期直接赠送都不影响它。首次赠送池独立抽取且不推进主池状态；周期赠送直接发放角色，不计入抽数。角色池的大保底目标取最高稀有度名单中排序第一的UP；周期自动赠送目标则从最高档向低档寻找第一个UP。

规则页还配置大保底、首次赠送池和周期直接赠送：

| 机制 | 行为与计数 |
|---|---|
| 大保底 | 连续主抽未获得绑定目标达到阈值时，本次主抽必得目标。仅主池结果满足目标；按“获得后关闭”或“获得后重置”继续。它不额外增加一次抽取。 |
| 首次赠送池 | 累计主抽到达触发位置后执行一次配置的赠送抽数。赠送池使用自己的概率和小保底，不继承主池保底；抽数计入赠送抽和总抽，不改变主池状态。 |
| 周期直接赠送 | 每经过设定的主抽周期直接给予目标角色及数量。它不是抽取，不增加任何抽数、不消费随机数、不发抽取奖励，也不改变保底。 |

规则机制目标通过绑定池解析：`首次UP角色`按稀有度从高到低取首个含UP角色档中名单顺序最前的UP；指定角色则要求池中存在有效绑定。启用大保底时目标须属于最高档。编辑角色名单、UP标记或顺序后会重新校验目标。

## 角色池

池绑定且只使用一条规则；实验不能覆盖规则。池编辑器按规则档位显示名单和奖励。池可覆盖档位显示名，但统计仍按稳定 ID 关联。没有角色名单的档仍可抽出稀有度结果，只是角色显示为未配置。

角色按所属档管理名称、权重、UP和限定标记。权重须为正数，只影响同档角色间的抽取比例，不改变档位概率。未启用该档UP分组时，全档角色按权重分配；启用后先按UP占比分配UP/非UP组，再在组内按权重分配。UP角色必须为限定角色；分配正概率的组必须至少有一个角色。标记UP本身不代表启用了UP概率分组。

奖励按稀有度 ID 配置，金额不能为负。修改规则结构时需要明确将池名单和奖励映射到新档，或确认清除无法映射的内容；名称相同不构成自动映射。规则目标绑定也要重新确认。保存时会检查规则修订号和完整池配置。

私有池可以公开只读使用或保持隐藏。池类型不能原地切换，通过复制产生新池；规则类型也通过复制转换。规则被引用时不能删除。导入或复制池需要再次校验使用者对池及其规则的权限。

## 实验与初始条件

实验参数包括每轮新增主抽数、轮数、随机种子和 Trace 开关。种子可留空由系统生成；实际种子会保存在结果中。高级初始条件包括历史累计主抽数 H、各个已跟踪档的小保底未满足数，以及大保底目标是否已获得/循环未命中数。

非零历史状态绑定确认上下文，包括规则 ID、稀有度顺序、大保底模式和目标。上下文变化时，页面要求重新确认；服务端也会验证，不能仅靠前端提示提交。关闭中的机制草稿不代表运行状态。保存实验后再次打开会重新校验当前规则与池。

开始模拟前的预览列出规则/池修订号、每轮及全实验主抽数、赠送抽数、总抽数、直接赠送角色数和预计 Trace 事件数，并显示下次触发位置。主抽数是本次新增主抽，不含历史和赠送；赠送抽是首次赠送池的真实抽取。

登录使用管理员创建的账号；系统不开放自助注册。首次密码按页面要求修改。点击“开始模拟”才会提交任务；结果页可查看本人最近任务进度并请求停止。停止是取消运行，不等于删除历史；成功写入历史后，筛选、查看和下载都读取已保存快照。历史重跑使用当前池/规则和原参数生成新运行，确认修订变化后提交，不覆盖旧记录。管理员可在管理页维护账号、处理任务和历史，规则/池服务端仍会校验所有权与权限。

## 结果、赠送与 Trace 口径

| 名称 | 统计口径 |
|---|---|
| 主抽数 | 本次主池抽取数，不含开始前历史与赠送池抽取。 |
| 赠送抽数 | 首次赠送池的抽取数，属于真实抽取。 |
| 总抽数 | 主抽数＋赠送抽数；不含周期直接赠送角色。 |
| 直接赠送角色 | 周期机制直接给予的数量；不属于抽取，不计算概率或奖励。每个触发位置是一条赠送事件，数量大于1仍只记一条事件。 |
| 角色获得合计 | 抽取获得＋直接赠送数量；不是抽取概率。 |
| Trace事件数 | Trace 开启时保存的抽取事件＋直接赠送事件；关闭时保存事件数为0。 |

赠送池抽取计入档位、角色及奖励统计，但不改变主池大保底、小保底或主抽累计。直接赠送只进入“直接赠送”和“角色获得合计”，不伪装成概率为1的抽取。Trace 逐抽明细仅在运行前开启时保存，之后不能补生成；关闭 Trace 的运行仍有汇总和理论结果。

结果页可查看摘要、分类统计、按抽次图表及逐事件列表。按抽次分析只适用于已保存 Trace，可选主池/赠送来源、计数/比例、轮次、来源位置和稀有度；筛选只改变展示。逐事件列表可按轮次、事件类型、来源、稀有度、角色和位置过滤。抽取事件带概率及抽前/抽后状态；直接赠送事件没有来源抽次和抽取概率。历史快照不随规则或池编辑变化；“按当前池重跑”会用当前资源创建新运行。

## CLI

CLI 读取新版 JSON 文件，适合离线分析，不写入网页历史：

```bash
python -m lottery_simulator analyze --pool-config configs/pools/default.json --draws 30
python -m lottery_simulator simulate --pool-config configs/pools/default.json \
  --draws 30 --trials 2 --seed 42 --trace
```

池文件通过规则引用解析规则；默认在 `configs/rules/` 按 ID 查找。可用 `--rule-directory` 指定目录，或用 `--rule-config` 指定匹配池引用的规则文件。ID 不匹配时不会静默替换；名称候选需要交互确认。模拟可用 `--initial-main-draws`、`--initial-small-pity`（JSON ID→整数）、`--initial-target-obtained` 和 `--initial-big-pity` 传入初始状态；状态须符合规则模式及确认上下文。Trace 可在 CLI 内存输出；大量历史事件使用网页流式保存/导出。

命令帮助列出 `analyze`、`simulate` 和 `export-trace` 的完整选项。旧格式和固定稀有度字段不属于新版 CLI 输入契约。

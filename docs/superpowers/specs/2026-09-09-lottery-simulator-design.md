# 抽奖模拟器设计

## 目标

构建一个以 Python 实现的本地抽奖模拟器。第一版实现一套六星动态保底规则，同时将规则、模拟执行与数学分析分离，使后续规则能够通过新增或替换模块演进，而不必修改模拟引擎。

第一版只提供命令行界面，不建设网页、账户系统或持久化数据库。

## 规则 1

设 `n` 为上一次抽到六星后进行的第几次抽取；首次抽取的 `n` 为 1。六星条件概率定义为：

```text
p(n) = 0.008                         1 <= n <= 64
p(n) = 0.008 + 0.05 * (n - 64)      65 <= n <= 79
p(n) = 1.0                           n = 80
```

关键边界：

- 第 64 抽概率为 0.8%。
- 第 65 抽概率为 5.8%。
- 第 79 抽概率为 75.8%。
- 第 80 抽概率为 100%。
- 抽到六星后，保底计数立即清零，下一抽重新作为第 1 抽。

虽然每次随机数生成相互独立，但六星事件的条件概率依赖连续未出次数，因此结果序列本身不是同分布的独立伯努利试验。

## 架构

### 规则层

`rules/base.py` 定义最小规则协议与状态类型。规则接收当前连续未出次数，返回下一抽六星概率；抽取后根据结果生成下一状态。

`rules/rule_1.py` 实现规则 1。概率函数保持无副作用，以便数学分析和测试直接复用。规则状态只保存 `misses_since_six_star`，不保存随机数生成器或统计结果。

### 模拟层

`engine.py` 负责：

- 使用调用方提供或由种子创建的随机数生成器；
- 执行单次、连续多次和多轮实验；
- 将随机结果交给规则更新状态；
- 返回结构化结果，不负责格式化终端输出。

固定随机种子必须产生可复现结果。规则层不得自行创建随机数生成器。

### 分析层

`analysis.py` 从规则提供的逐抽概率计算：

- 首次六星所在抽数的概率质量函数和累计分布；
- 平均六星间隔、方差、标准差、中位数、众数和分位数；
- 指定有限抽数内六星数量的精确期望；
- 模拟值与理论值之间的误差。

等待时间 `T` 的精确分布为：

```text
P(T = n) = p(n) * product(1 - p(k), k = 1 ... n-1)
```

平均间隔为 `E[T] = sum(n * P(T=n))`，长期综合六星率为 `1 / E[T]`。指定有限抽数内的六星数量使用状态动态规划计算，不直接用 `抽数 / E[T]` 代替。

规则 1 的基准值为：

- 平均间隔约 `53.32595` 抽；
- 长期综合六星率约 `1.87526%`；
- 标准差约 `22.63187` 抽；
- 中位数为第 67 抽；
- 众数为第 68 抽；
- 90%、95%、99% 分位数分别为第 72、73、75 抽；
- 到第 80 抽触发硬保底的概率约 `0.00730237%`。

这些数值是回归基准，不作为规则实现里的硬编码输出。

### 命令行层

`cli.py` 提供两个首版命令：

- `analyze`：输出规则概率表与精确理论指标；
- `simulate`：执行单轮详细模拟或多轮统计模拟，并输出其与理论值的误差。

批量模拟入口：

```bash
python -m lottery_simulator simulate \
  --draws 100 \
  --trials 100000 \
  --seed 42
```

单轮详细模拟入口：

```bash
python -m lottery_simulator simulate \
  --draws 100 \
  --trials 1 \
  --seed 42 \
  --trace
```

精确分析入口：

```bash
python -m lottery_simulator analyze
```

`simulate` 首版参数固定为：

| 参数 | 默认值 | 约束与含义 |
| --- | --- | --- |
| `--rule` | `rule1` | 选择已注册的规则模块 |
| `--draws` | 无，必填 | 每轮总抽数，必须为正整数 |
| `--trials` | `1` | 独立重复轮数，必须为正整数 |
| `--seed` | 不指定 | 可选整数随机种子；指定后结果可复现 |
| `--initial-pity` | `0` | 开始前连续未出六星次数；规则 1 接受 0 至 79 |
| `--trace` | 关闭 | 输出逐抽详情；仅允许在 `--trials 1` 时使用 |
| `--format` | `text` | 输出格式，只接受 `text` 或 `json` |

逐抽详情包含当前模拟抽次、保底位置、本抽六星概率、抽取结果和抽后保底状态。批量统计包含平均六星数量、至少获得一个六星的比例、六星数量分布、模拟平均间隔、理论平均间隔和误差。示例或文档不得把一次随机模拟的输出写成固定基准。

`initial_pity` 表示模拟开始前已经连续未出六星的次数。例如 `--initial-pity 60` 时，模拟的第一抽是保底周期中的第 61 抽。抽到六星后仍按正常规则清零。

第一版不加入并行度、CSV、图表或命令行概率覆盖参数。概率常量集中保存在规则模块中，输出必须包含规则名称、抽数、轮数、初始保底状态和实际使用的种子，使实验可追溯。未显式指定种子时，引擎生成种子并在结果中显示它。

参数错误使用清晰的错误消息和非零退出码。概率、抽数和轮数在边界处校验；第一版不读取不可信的规则表达式或执行配置文件代码。

### Python 调用入口

模拟引擎提供与 CLI 无关的 Python 接口，供测试和未来展示层复用：

```python
result = simulate(
    rule=Rule1(),
    draws=100,
    trials=100_000,
    seed=42,
    initial_pity=0,
)
```

函数返回结构化结果，不直接打印。`trace` 和 `format` 属于 CLI 的展示选项，不进入核心模拟接口；单轮明细由结构化结果中的抽取记录提供。

## 数据流

```text
CLI 参数 -> 选择规则 -> 分析器或模拟引擎 -> 结构化结果 -> CLI 格式化输出
                         |                  |
                         +---- 规则模块 ----+
```

模拟中的每一抽按以下顺序执行：读取状态、取得条件概率、生成随机数、判定结果、更新状态、记录结果。数学分析直接调用相同的概率函数，避免维护第二份概率表。

## 错误处理与数值约束

- 规则返回的概率必须位于 `[0, 1]`；否则立即报错。
- 抽数与实验轮数必须为正整数，并设置合理的命令行上限或明确警告，避免误输入导致超长运行。
- 概率累计计算使用 Python 双精度浮点数；当前最多 80 个状态，误差足够小。
- 精确分布的概率和必须在浮点容差内等于 1。
- 模拟误差只用于评估随机结果，不用于证明规则实现正确。

## 测试与验证

保留一个轻量、可直接运行的标准库测试集，不增加第三方测试依赖。至少验证：

- 第 1、64、65、79、80 抽概率分别正确；
- 第 80 抽必出；
- 六星后状态清零，下一抽回到 0.8%；
- 分布概率和为 1；
- 理论均值、标准差和关键分位数匹配基准；
- 固定种子结果可复现；
- 有限抽数期望的动态规划在小规模下与穷举结果一致。

修改非平凡逻辑后执行完整测试。涉及规则边界的修复还应做正反验证：引入边界错误时测试失败，恢复正确实现后测试通过，以确认测试确实覆盖目标行为。

## 暂不包含

- 图形或网页界面；
- 多星级、角色与物品明细；
- UP、大小保底或抽取货币；
- 用户账户、数据库与联网功能；
- 用 JSON/YAML 表达任意条件逻辑。

这些能力只有在具体规则确定后再以新规则模块或展示层扩展。

## 验收标准

1. 用户可运行精确分析并得到上述规则 1 基准指标。
2. 用户可指定规则、抽数、实验轮数、种子和初始保底状态运行模拟。
3. 单轮跟踪能显示逐抽概率、结果和状态变化；批量模式能显示统计分布及理论误差。
4. 文本和 JSON 输出均包含复现实验所需的实际参数与种子。
5. 模拟引擎不包含规则 1 的概率常量。
6. 替换规则实现时，无需修改模拟引擎。
7. 所有标准库测试通过，理论值与规则边界均有直接测试。

## 1. 执行边界与阅读要求

先读设计及[开发与验证](../standards/development.md)、[变更记录](../standards/change-records.md)；按任务查看[架构与数据](../standards/architecture-data.md)、[权限与资源](../standards/permissions.md)、[界面与交互](../standards/ui-interaction.md)、[部署与数据保护](../standards/deployment-safety.md)。规范全文不在计划中复制。

- 计划沿用一份主题文档，按计算/接口、网页、部署三条主线组织；每条主线可独立验收，不相互冒充完成。
- 实施开始时选择隔离工作区，保留用户已有修改；新建同主题实施记录 `docs/changes/2026-10-07-current-update-legacy-reinstall.md`，关联设计和本计划。现在不创建空实施记录。
- 同一功能关联修改连贯完成后集中验证。修复先确认原问题，可复用可信证据；稳定问题通常只需修复前失败、修复后通过。因果不清时才增加隔离对照，不逐任务默认全套回归、多轮审查或提交。
- 不新增抽卡机制、动画、多语言、自动保存、配置合并、队列或迁移框架。抽样语义改变时按R1更新抽样版本，不能伪装为旧算法复现；同格式抽样版本2/3历史只读展示及导出，执行与新写入仍严格当前3，历史快照不重写。
- 网页种子上限为4300位十进制数字，负号不计入；有效上限按设计R5取Python非零限制与项目上限的较小值，环境无限制时仍限4300位。管理员不得绕过；CLI离线契约不随之扩大修改。
- 永久删除只限设计中的已核对项目资源，必须展示实际清单并双确认；禁止用整目录删除、全机prune、自动覆盖数据库或自动重试替代保护。
- 本地验证只用临时数据与测试账号，不连接现有业务库。真实服务更新、卸载、恢复和删除须在执行时获得明确授权，计划确认不代替该授权。

### 中间阶段保持可运行

计算和后端修复沿用现有API、数据库及任务格式；共享校验接入后现有前端仍能调用。网页共用组件随规则页一起落地，再逐页接入，未改页面继续使用原入口，不挂载第二套应用或临时自动写库逻辑。

执行中的前端开发服务只连接本工作区的隔离后端。若R1改变抽样版本，旧任务在原版本完成或保留原现场；测试使用新任务目录，不让新worker接续旧版本活动任务。部署任务完成前只在替身/隔离环境运行新脚本，不把半成品发布到服务器。旧业务及历史文件不因中间测试被清空。

### 任务1：统一概率尾差处理

**涉及文件：** `lottery_simulator/probability.py`、`rules/runtime.py`、`rules/definitions.py`、`analysis.py`、`waiting_analysis.py`、`formats.py`；按实际调用核对`engine.py`和`events.py`。

**交付契约：** 概率计算层返回已经校验及修正的分布；`rarity_probabilities()`、`character_probabilities()`现有返回类型不变，抽样、有限期望、等待分析与Trace消费同一向量，不消耗额外随机数。

- [x] 用设计R1的两档300抽、单档等待最小用例确认原现象；已有动态证据可复用，不把静态推断直接记作复现。
- [x] 在`probability.py`集中有限非负校验和容差内确定性修正，runtime的`_check_distribution()`复用它。保持输入顺序，零概率不变，超出`1e-12`仍拒绝；空角色名单继续表示无具体角色，不送入非空分布校验。修正不得使极小正概率项变为负数。
- [x] 核对稀有度/角色、主池/赠送池、理论分支及等待分析调用，消除只在执行器补差的分歧；不提高理论守恒容差掩盖问题。
- [x] 检查抽样区间、顺序和随机数使用是否改变；语义改变则提升`sampling_version`及对应说明。不能仅凭几个相同种子结果就认定算法完全未变。

**完成判据：** 阶段验收A中的R1场景通过，理论和模拟使用同一分布，版本影响已说明。

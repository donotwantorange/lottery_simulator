# 规则 1 多星级、角色池、五星保底与附赠奖励设计

日期：2026-09-14  
状态：已实现（2026-09-16 本地完整自动化回归 228 项通过；三项 CLI 验收通过；服务器现场验收仍未执行）
目标规则版本：`2.0`

## 1. 目标与范围

在现有规则 1 的六星动态保底和首次 30 次主抽赠送 10 抽基础上，增加：

- 四星、五星、六星三级完整结果；
- 可关闭、可修改阈值的独立五星保底；
- UP 六星、其他限定六星、常驻六星和具体六星角色；
- 多 UP 及 UP 内部权重；
- 每抽可同时结算多种、按星级取值的附赠奖励；
- 主池与赠送临时池的独立双保底状态；
- 相应的模拟统计、精确理论期望、Trace、新版历史快照和网页编辑能力。

本次不增加独立的配置模板数据库，也不扩大到真实服务器部署测试。默认配置、JSON 导入导出和历史参数复用覆盖当前个人使用场景。

## 2. 已确认的概率规则

### 2.1 主池六星概率

沿用规则 1 版本 1.2 的六星概率：

```text
p6(n) = 0.008                         1 <= n <= 65
p6(n) = 0.008 + 0.05 * (n - 65)      66 <= n <= 79
p6(n) = 1.0                           n = 80
```

其中 `n` 是当前六星保底周期内的抽数。主池抽到六星后六星保底清零。

### 2.2 普通星级概率

未触发五星保底时：

```text
六星概率 = 当前 p6
五星概率 = 配置的基础五星概率，默认 0.08
四星概率 = 1 - 六星概率 - 五星概率
```

因此普通阶段为 0.8% / 8% / 91.2%；软保底提高六星概率时，五星仍为 8%，四星吸收变化。例如第 66 抽为 5.8% / 8% / 86.2%，第 79 抽为 70.8% / 8% / 21.2%。

### 2.3 五星保底

五星保底默认开启，阈值默认 10 抽，语义是“至少五星”：

- 连续 9 抽未出现五星或六星后，第 10 抽先保留当前六星概率；
- 若未命中六星，剩余概率全部归五星，四星概率为 0；
- 五星重置五星保底，但不重置六星保底；
- 六星同时重置五星和六星保底；
- 四星同时推进两个保底；
- 第 80 抽六星为 100%，优先于五星保底；
- 关闭五星保底后，只使用基础五星概率，五星状态按 0 处理。

只要抽取前五星未出计数已到阈值前一位，本抽就记为“五星保底已触发”，即使本抽最终命中六星；该指标表示到达了保底抽，不表示结果一定是恰好五星。六星硬保底触发同理，表示本抽位于六星保底周期第 80 抽。

状态转移如下：

| 抽取结果 | 六星未出计数 | 五星及以上未出计数 |
|---|---:|---:|
| 四星 | +1 | +1 |
| 五星 | +1 | 清零 |
| 六星 | 清零 | 清零 |

## 3. 六星角色池与概率分配

六星角色以具体条目配置，不单独维护容易失配的 `T/U/L` 数量字段。系统由角色表自动推导：

- `T`：六星角色总数；
- `U`：UP 六星角色数；
- `L`：限定六星角色数，包含全部 UP。

设 UP 六星合计占六星结果的 `R`，默认 `R = 0.5`：

```text
单个 UP 的六星内占比
= R * 该 UP 权重 / 全部 UP 权重之和

单个非 UP 的六星内占比
= (1 - R) / (T - U)

限定六星总占比
= R + (L - U) * (1 - R) / (T - U)
```

UP 内部按权重分配；所有非 UP 六星彼此等概率。UP 必须同时标记为限定。

当全部角色都是 UP 时，只允许 `R=1`，所有角色按 UP 权重分配；此时不计算非 UP 公式。`R<1` 时必须至少存在一个非 UP 角色。

默认角色池共 9 名，`T=9、U=1、L=3`：

| 角色 | UP | 限定 | UP 权重 |
|---|---|---|---:|
| UP-A | 是 | 是 | 1 |
| 限定-B | 否 | 是 | — |
| 限定-C | 否 | 是 | — |
| 常驻-D | 否 | 否 | — |
| 常驻-E | 否 | 否 | — |
| 常驻-F | 否 | 否 | — |
| 常驻-G | 否 | 否 | — |
| 常驻-H | 否 | 否 | — |
| 常驻-I | 否 | 否 | — |

默认配置下，UP-A 占六星结果 50%；其余 8 名角色各占 6.25%；限定六星合计占 62.5%，常驻六星合计占 37.5%。

## 4. 附赠奖励

一次抽取同时结算所有已配置奖励。每种奖励分别配置四星、五星和六星的固定值；值只由星级决定，不因 UP、限定或具体角色改变。值为 0 表示该星级不发放该奖励。

默认占位配置：

| 奖励 | 四星 | 五星 | 六星 |
|---|---:|---:|---:|
| 奖励A | 1 | 5 | 25 |
| 奖励B | 0 | 2 | 10 |

例如五星会同时发放奖励A ×5 和奖励B ×2。奖励条目可增删，名称和数值可修改。

## 5. 核心模型

### 5.1 不可变配置快照

`PoolConfig` 由以下配置组成：

- `up_share`；
- `FiveStarPolicy`：基础概率、保底开关、保底阈值；
- `SixStarCharacter` 列表：名称、是否 UP、是否限定、UP 权重；
- `RewardRule` 列表：名称和三个星级的奖励值。

默认配置保存在 `configs/rule1_default.json`。加载或网页编辑后的可变数据必须先验证并转换为不可变配置，后台任务只接收该快照。运行过程中继续编辑页面不会改变正在执行的任务。

现有实现中的 `DrawState` 可保留名称以减少兼容性改动，但扩展为概念上的 `PoolState`：

```text
misses_since_six_star
misses_since_five_or_higher
```

第二个字段默认 0，以兼容仅传六星状态的旧调用。

### 5.2 单抽结果

`DrawOutcome` 至少包含：

- `rarity`：4、5 或 6；
- `six_star_character`：仅六星时存在；
- `is_up`、`is_limited`；
- `five_star_pity_triggered`、`six_star_hard_pity_triggered`；
- 本抽全部奖励明细；
- 抽取前后双保底状态。

现有 `is_six_star` 可作为 `rarity == 6` 的兼容字段继续输出，避免旧消费者无故失效。

### 5.3 单抽数据流

```text
读取配置与池状态
→ 计算当前六星概率
→ 计算是否触发五星保底及 4/5/6 星概率
→ 使用随机数抽取星级
→ 若为六星，再按角色条件概率抽取具体角色
→ 按星级结算所有奖励
→ 更新双保底状态
→ 返回结构化结果
```

固定种子必须复现完整星级、具体角色和奖励结果。

## 6. 首次 30 抽赠送临时池

首次 30 抽赠送机制仍是独立子规则：累计完成第 30 次主池抽取后触发一次，每轮最多一次；开始时主池累计抽数已达到 30，仍视为已经领取。

触发时复制主池的池内容配置来创建一个新的临时池，而不是复制主池当前运行状态。临时池共享：

- 具体六星角色列表；
- UP 合计占比及 UP 内部权重；
- 限定标记；
- 五星基础概率；
- 附赠奖励配置。

临时池覆盖：

- 抽数固定为 10；
- 六星概率固定为 0.8%，不使用主池软保底；
- 五星保底强制开启且阈值为 10；
- 双保底状态从 0 开始；
- 不挂载首次 30 抽赠送子规则，避免递归触发。

临时池中的五星或六星都满足十连“至少五星”保底。十抽完成后销毁临时池状态。赠送抽不会增加或重置主池五星、六星保底，也不会推进主池累计抽数。

## 7. 入口与编辑方式

### 7.1 网页

主要模拟参数区继续保留：

折叠的“奖池与奖励设置”提供：

第一版不单独建立命名模板管理页。用户可通过默认配置、JSON 文件和历史“复用参数”复用配置。

### 7.2 命令行

新增可选参数：

```text
--pool-config PATH
--initial-five-star-pity N
```

未提供 `--pool-config` 时加载默认配置；初始五星保底默认 0。现有 `--initial-pity` 保持六星保底与开始前累计主抽数的双重语义，继续决定首次 30 抽赠送资格。

## 8. 配置校验

所有入口调用同一个校验实现，并在任务创建或历史写入前拒绝错误：

- 角色名称、奖励名称必须非空且各自唯一；
- 至少有一个六星角色和一个 UP；
- 所有 UP 必须是限定，UP 权重必须为有限正数；
- `0 < up_share <= 1`；UP 占比小于 1 时必须存在非 UP；
- 五星概率必须在 `[0, 1]`，五星保底阈值必须为正整数；
- 对六星保底所有可达位置检查普通星级概率非负且总和为 1；
- 奖励值必须是有限非负数；
- 五星保底开启时，初始五星保底必须位于 `0..hard_pity-1`；关闭时强制为 0；
- 角色和奖励列表不得使用布尔值冒充数字。

JSON 格式错误和配置语义错误显示安全、具体的中文错误；后台失败不产生不完整历史记录。

## 9. 模拟结果与理论分析

每轮分别累计主池、赠送临时池和总计结果：

- 四星、五星、六星数量及每轮均值；
- 至少一个五星及以上、六星、UP 六星、限定六星的轮次比例；
- 五星保底触发次数、六星硬保底触发次数；
- UP、其他限定、常驻六星数量；
- 每个具体六星角色的数量、占全部六星比例和占总抽数比例；
- 每种奖励的总量、每轮平均量和每轮总量分布；
- 六星数量分布及新增的星级、六星类别拆分。

有限抽数理论分析使用双状态动态规划：

```text
状态 = (连续未出六星数, 连续未出五星及以上数)
```

它精确计算主池和赠送临时池各自及合计的：

- 四星、五星、六星期望；
- UP、限定、常驻和每个具体六星角色期望；
- 每种奖励期望；
- 五星保底触发期望。

角色在六星中的条件概率固定，因此具体角色期望由六星期望乘以角色条件占比得到，无需把角色身份加入动态规划状态。

五星保底不改变六星概率，现有六星首次出现分布、完整周期平均间隔和长期六星率继续按六星规则计算。它们与新增星级、奖励有限抽数分析分开呈现。

非 Trace 模拟继续流式累计计数，不保存每抽对象，内存使用不随抽数和轮数线性增长。双状态精确分析仅保留可达状态，状态数上限约为 `80 × 五星保底阈值`；第一版时间复杂度仍与有限抽数成正比。若该精确分析成为超长单轮的瓶颈，后续再增加周期加速；本次不引入矩阵库或未经需求验证的复杂优化。

## 10. 网页结果布局

结果区分为：

1. 总览：抽数、各星级模拟均值与理论期望；
2. 六星构成：UP、其他限定、常驻对比；
3. 具体角色：每名六星角色的模拟数量、实际占比、理论占比和误差；
4. 附赠奖励：每种奖励的均值、理论期望和分布；
5. 保底统计：五星保底与六星硬保底触发情况；
6. Trace：每抽概率、星级、角色、奖励、来源、保底触发及前后双保底状态。

主池、赠送和总计保持可拆分查看。非 Trace 批量模拟只保存汇总和配置，不保存逐抽记录，延续现有内存与历史策略。

## 11. 新版历史数据库

规则版本从 `1.2` 提升为 `2.0`。本次不实现旧历史迁移，默认数据库由 `data/history.sqlite3` 改为：

```text
data/history_v2.sqlite3
```

- 原 `data/history.sqlite3` 不读取、不迁移、不覆盖、也不自动删除；
- 新数据库使用适配结构化抽取结果的全新 schema；
- 若 `LOTTERY_DB_PATH` 显式指向旧 schema，程序安全拒绝并提示数据库版本不兼容；
- 新模拟保存完整 `pool_config` JSON 快照和初始五星保底；
- 新 Trace 保存星级、角色、UP/限定、五星状态、保底触发及奖励 JSON；
- 丰富统计保存在结果快照，常用筛选字段才进入独立列；
- 新版历史复用恢复当次完整配置；
- 对比不同配置时同时显示规则版本和配置摘要。

不以 SHA 作为功能依赖或额外验证步骤。

## 13. 已确认决策摘要

- ✅ 多 UP 合计占六星 50%，内部可配置权重；其他六星等概率。
- ✅ 默认六星池 9 名，1 名 UP、3 名限定（包含 UP）。
- ✅ 五星基础概率 8%，四星吸收六星软保底变化。
- ✅ 五星保底默认 10 抽、可关闭，六星视为满足五星保底。
- ✅ 初始五星保底为高级可选参数，默认 0。
- ✅ 赠送 10 抽使用配置克隆的临时池，自带独立十抽五星保底。
- ✅ 保留具体六星角色统计。
- ✅ 多种奖励按星级同时结算，默认使用奖励A、奖励B示例值。
- ✅ 配置采用不可变对象、默认 JSON、网页表格编辑及 JSON 导入导出。
- ✅ 新版历史保存完整配置快照；不实现旧历史迁移，旧数据库文件保持不动。

## 2. 总体架构

后端采用Django 5.2 LTS与兼容DRF版本，前端采用React、TypeScript、Vite及React Router。实施时核对Python/Node兼容范围并锁定具体版本，提交Python依赖及npm锁文件，不依赖全局安装的前端工具。Django负责认证、会话、CSRF、ORM和迁移；DRF负责JSON请求解析、序列化、校验、分页与接口权限入口。业务对象权限仍由项目服务层实现，不假定框架自动隔离数据。React负责业务页面、交互状态、图表容器与未来动画组件。

建议目录职责如下（具体拆文件由计划落实）：

```text
manage.py                  # Django命令入口
webapp/                    # settings、urls、wsgi
dashboard/                 # Django应用、模型、服务、API、序列化器
  management/commands/     # 初始化、恢复、解锁及工作进程入口
frontend/                  # 独立npm工程，Vite构建
  src/api/                 # 统一请求、错误、CSRF与类型契约
  src/pages/               # 登录及已确认的五个业务页面
  src/components/          # 表单、表格、图表等组件
  src/features/            # 按账号、池、实验、结果组织交互
  dist/                    # 构建产物，不手工编辑
lottery_simulator/         # 纯配置契约、模拟、理论、统计及CLI
configs/                   # 默认池与实验示例
```

保留现有统计与Altair图表构建可复用部分，API返回受控Vega-Lite规格，由React图表组件封装vega-embed渲染并在卸载时释放实例。显式声明后端Altair及前端图表依赖，由Vite打包，不依赖外部CDN。图表规格仅来自后端，不接受上传的任意脚本或外部数据URL。图表数据仅取有权限的汇总/分页聚合，不把整份Trace送到浏览器。未来动画组件消费同样的数据契约，不把抽样算法搬到前端。

将纯模拟参数合法性校验和网页业务限额分开；身份不进入抽样算法。网页服务层负责认证授权、加载池、冻结参数、派发任务；工作进程只消费服务端已接受的任务快照。所有网页入口（包括下载、历史复用、查询明细、失败结果重存）都走服务层，不能直接凭记录ID调用裸仓库接口。

普通操作由React提交同源API请求，不使用Django业务模板或HTML重定向作为API结果。统一fetch客户端处理CSRF、会话失效、错误和取消请求；进度暂用轮询，不引入WebSocket。复用现有任务锁、取消协议、Trace分批写入、汇总序列化与理论计算，适配Django持久层。严禁缓存跨用户授权决定或未带用户键的私有数据；仅维护一套当前React业务界面。

## 3. 业务对象与规则

公共池、公开私有池、实验配置和历史快照是不同对象，不能混用其权限或生命周期。

### 3.1 角色池与规则

包含稳定ID、名称、使用的规则标识、四五星和六星名单、UP占比及权重、奖励表、现有五星概率及保底配置、稀有度显示名称。

一个池指定一个规则，多个池可以使用同一规则。实验不能覆盖池指定的规则。不另建池与规则的映射表；保留程序中规则标识到实现的加载机制。

规则算法、六星基础与递增概率及硬保底、赠送子规则的现有固定参数继续留在Python实现中。现有五星概率和保底配置留在池中。理论分析与模拟继续使用共同规则公式和接口。

### 3.2 实验配置

包含名称、角色池引用、每轮主抽数、轮数、初始六星及五星保底进度、种子和Trace开关。实验配置按用户隔离，不能重复维护一份可覆盖角色池的规则选择。

配置引用用于复用；执行时解析并校验完整配置，生成快照。运行中的任务不能随原配置编辑而改变。

### 3.3 池归属、复制与署名

公共池归系统公共资源，不绑定某个管理员作为所有者，由所有管理员共同管理；私有池绑定所属用户。私有池复制为公共池仅允许管理员操作，新池成为系统公共资源；公共池复制为私有池允许有权查看的用户操作，新池归复制者。类型转换一律以复制实现，新池分配新ID，原池和原引用不变，不原地切换类型。私有池的公开/隐藏切换不属于类型转换。

复制始终保留最初作者署名，不累积中间复制者名单。署名为创建时保存的独立文本，原作者改名或账号删除后也不改变；署名仅作来源说明，不授予所有权和编辑权限。

私有池复制默认归复制者且隐藏；角色池复制始终生成新ID，原池和原引用不变。操作权限见第4章，文件导入署名见第9章。

### 3.4 稀有度显示名称

角色池增加可选`rarity_labels`：

```json
{"4": "四星", "5": "五星", "6": "六星"}
```

可以配置为R、SR、SSR等名称。内部计算及存储继续使用4、5、6；缺省采用原名称。网页、图例、Trace明细、中文报告中的稀有度展示统一读取映射，结构化字段标识不因改名而变化。

映射保存在实验快照中，历史使用自己的名称，而非当前角色池的新名称。UP和限定仍为角色属性，不混入稀有度映射。

显示名称允许省略或部分填写，缺少键使用默认名；仅允许4/5/6三个键，值为去首尾空白后的非空文本，最长32字符，三档名称不得相同。对外JSON和程序字段继续用稳定星级编号，中文标题、表格和错误提示通过公共显示函数取名，不能字符串全局替换。“UP六星”等组合名称使用映射，例如“UP SSR”。

### 3.5 名称与引用

同一用户的私有池名称唯一，公共池之间名称唯一，实验配置名称在同一用户内唯一。不同用户私有池允许同名，展示名称及所属用户；导入重名提示改名，不覆盖。规范化和数据库约束见5.3节。

原池隐藏或删除后，已完成实验和已启动任务继续使用已有快照，不受影响；尚未启动的实验配置若无权访问原池或原池已不存在，必须重新选择可用池，不能通过旧引用或旧快照绕过启动权限。

## 4. 账号与权限

本地开发和服务器均要求本地用户名/密码登录，不开放注册，不提供默认密码或免登录管理员权限。匿名用户只能使用登录所需页面与认证接口，不能读取业务资源。

### 4.1 权限矩阵

| 资源或操作 | 普通用户 | 管理员 |
|---|---|---|
| 实验配置管理 | 仅自己的 | 全部 |
| 历史和Trace查看、下载、删除 | 仅自己的 | 全部 |
| 模拟任务查看、停止 | 仅自己的 | 全部 |
| 账号管理 | 不允许 | 允许 |
| 公共池查看和使用 | 允许 | 允许 |
| 公共池修改 | 不允许 | 允许 |
| 公开私有池查看和使用 | 允许 | 允许 |
| 隐藏私有池查看和使用 | 仅创建者 | 允许 |
| 私有池修改 | 仅创建者 | 允许 |

公共池仅管理员可删除；私有池由所属用户或管理员删除。有权查看池的登录用户可以复制和导出，复制为公共池仅管理员可操作。

公开私有池不变成公共池，其他用户不能修改原池。公开仅指对登录用户公开，不允许匿名访问。使用他人角色池产生的实验归执行用户所有。

实验配置、任务和历史记录绑定稳定用户ID。所有读取、下载、修改、删除及停止入口都必须在服务端校验权限，不能仅靠网页隐藏按钮，也不能信任客户端传来的所有者或角色。

### 4.2 账号管理与生命周期

管理员可以创建、编辑、删除、禁用和启用账号。编辑支持修改用户名、重置密码及调整普通用户/管理员角色。用户名或角色变更使已有会话失效，稳定用户ID和数据归属不变。普通用户仅能自助修改密码，不能修改用户名或角色。

管理员不能删除自己；最后一个可用管理员不能被删除、禁用或降级。账号启用/禁用不删除数据。修改密码、用户名、角色及禁用会话的技术处理统一见10.2节。

普通用户自助改密需验证当前密码；管理员创建或重置的密码首次登录必须修改，未完成前不可使用业务功能。忘记密码由管理员重置，不提供邮件找回。首个管理员与本机恢复见6.1及11.1节。

### 4.3 账号变化对任务和数据的影响

账号角色变化不停止已启动任务，任务继续按提交时通过校验的参数执行；后续新实验和下载按新角色校验。禁用也不自动停止任务，但删除账号必须先停止任务。公共池不绑定具体管理员所有权，管理员被删除、禁用或降级均不需要转交公共池，也不改变其最初作者署名。

账号与历史逻辑分离，删除实验不删除账号。删除账号的数据范围和失败处理仅以6.5节为准；公共资源归属见3.3节。

### 4.4 服务端授权边界

服务层身份来自经中间件验证的request.user，不接受客户端owner或admin标志。普通用户查询在ORM/服务层附加owner条件；列表、单条、Trace、图表聚合、下载和失败结果重存均覆盖。无权与不存在对普通用户统一404；未登录/过期统一JSON 401，禁止返回登录HTML。DRF SessionAuthentication的默认未认证状态可能是403，需在公共异常层明确区分并规范为401；CSRF失败保持403，不可误转为登录成功。前端401清私有画面和缓存，停止轮询。全局busy仅返回布尔，详情仅本人或管理员可取。

### 4.5 管理员代管实验配置

管理员编辑他人实验配置时，池选择必须是该配置所有者有权使用的池，不能以管理员视角保存一个所有者无法运行的引用；管理员使用该配置另起实验时，新记录归管理员本人。普通用户看不到其他人的配置名称和引用统计。

## 5. 数据模型与存储

配置示例文件与网页数据库分工明确，不双向自动同步。

### 5.1 存储位置与职责

逻辑目录为`configs/pools/`和`configs/experiments/`，用于默认配置、示例及JSON导入导出。

已确认：网页创建和修改的配置保存到SQLite，分别建立角色池配置表和实验配置表。稳定ID、名称、归属、可见性作为字段，角色、奖励和具体参数以JSON保存，不另拆角色或奖励表。由Django模型及迁移统一管理结构，结构见本章。默认示例文件与网页数据库不进行双向自动同步。

使用一个新库`data/history_v5.sqlite3`，同时存账号、配置、历史和会话，便于账号删除时在同一事务内处理关系。账号与历史逻辑分离：普通历史删除只触及运行/逐抽表，不删除用户。默认任务目录`data/jobs_v5/`，下载临时目录`data/exports_v5/`。保留现有数据目录与数据库路径环境变量，但不得将新建逻辑直接覆盖旧库。

### 5.2 表结构与框架所有权

| 表 | 关键字段及约束 |
|---|---|
| users | 从AbstractUser建立自定义用户模型：UUID主键、username、username_key唯一、Django password字段、is_active、must_change_password、auth_version、deleting、时间戳；is_superuser为业务管理员唯一判据 |
| django_session | 使用Django数据库会话后端原生表和序列化机制，不另建自制令牌表；会话内容加入auth_version、created_at、last_activity_at |
| login_limits | scope(account/source)、key、failure_count、window_start、blocked_until；联合主键，事务更新 |
| pools | UUID主键、name、name_key、kind(public/private)、owner_id可空、visibility(public/hidden)、original_author文本、rule_name、config_json、revision、时间戳 |
| experiment_configs | UUID主键、owner_id、name、name_key、pool_id可空、pool_name_hint、parameters_json、revision、时间戳 |
| simulation_runs | 复用现有字段，增加owner_id、pool_id_snapshot、pool_revision_snapshot、pool_name_snapshot、original_author_snapshot；完整快照仍进result_json |
| draw_records | 继续通过run_id关联；保留既有轮次、抽次和筛选索引；无单独角色或奖励表 |
| app_meta | 初始化完成标记等简单键值；不以公共池当前是否存在判断是否需要重新导入 |

使用AUTH_USER_MODEL并从首个迁移创建自定义用户。is_active对应启用状态；is_staff随管理员标志同步但不作为另一套业务角色，不提供任意组权限组合。Django附带的认证/内容类型/迁移记录表由框架管理。项目的“管理员页面”为受控自定义视图，不开放原生admin站点直接删账号或改角色绕过保护。

所有主库DDL由Django migrations唯一负责；新库仍用PRAGMA user_version=5作应用格式标记，但不再让旧HistoryRepository自行执行CREATE TABLE。账号/池/配置/历史用ORM管理，逐抽批量写入和聚合可以复用参数化SQL，但使用Django提供的同一事务连接，不混用独立sqlite3连接参与同一业务事务。临时Trace数据库仍由原TraceWriter管理，导入时复用分批读取，不逐行实例化百万个模型。

### 5.3 关联与唯一约束

公共池约束：owner_id为NULL且visibility=public；私有池必须有owner_id。公共池不依赖作者账号外键。私有池删除不级联删除别人的实验配置：experiment_configs.pool_id使用ON DELETE SET NULL并保留名称提示。历史中的池ID仅作来源快照，不作级联外键。draw_records仍随run删除。

名称去首尾空白后必须非空；名称键用Unicode NFC规范化，池名和实验名区分大小写。公共池name_key全局唯一，私有池(owner_id,name_key)唯一，实验配置(owner_id,name_key)唯一。用户名使用NFC后casefold作为唯一键，显示保留规范化文本；1至64字符，拒绝控制字符。所有SQL参数化，启用foreign_keys，写事务短持有，不在密码哈希或模拟期间占数据库写锁。

### 5.4 事务与并发

SQLite设置适当busy timeout和IMMEDIATE事务模式，ATOMIC_REQUESTS关闭；只在明确写入段使用transaction.atomic，不将下载、模拟或整页请求包进写事务。不能依赖SQLite无效的select_for_update提供行锁。全站任务锁与账号删除协调保留；涉及两类锁时固定先任务锁、后数据库事务，禁止反向获取。数据库暂忙返回可重试中文错误，任务提交不能盲目重试并重复启动。

账号删除、禁用、降级的最后管理员检查与更新必须在同一写事务内完成，不能两个管理员并发操作后留下零个可用管理员。私有池的owner与实验配置/历史owner均引用users；公共池的owner为空，绝不因删除作者账号而级联删除。

### 5.5 历史快照与格式版本

历史保存所属用户、实际实验参数、完整池快照（含奖励、规则引用、名称映射）、规则及抽样版本、汇总，以及开启Trace时的逐抽明细。

池被修改、隐藏或删除不改变已完成实验的内容。精确重跑仍依赖对应版本的规则及抽样实现；不能只凭规则名称承诺跨版本复现。

版本明确为：CONFIG_FORMAT_VERSION由1升2，新增EXPERIMENT_FORMAT_VERSION=1；RESULT_FORMAT_VERSION由2升3、JOB_FORMAT_VERSION由2升3、DATABASE_SCHEMA_VERSION由4升5。RECORD_FORMAT_VERSION=2、TRACE_STORE_FORMAT_VERSION=1、TRACE_EXPORT_FORMAT_VERSION=1、SAMPLING_VERSION=1保持不变：逐抽结构与随机消耗不变。rule1版本仍为字符串“2.0”；所有格式版本为严格整数，拒绝bool。旧格式明确拒绝，错误中文说明；不做自动迁移。

## 6. 核心流程

流程依赖第4章授权和第10章安全校验；不能只依赖前端按钮状态。

### 6.1 首次初始化

首个管理员通过本机命令交互创建，密码不回显；没有网页初始化入口。migrate完成后，在同一事务创建管理员、默认公共池和初始化标记。重复调用拒绝重建；默认池后来删除也不自动重生，默认作者为“项目默认配置”。

默认实验仅为示例，用户明确保存才归自己；后续重启不覆盖网页配置。具体命令见11.1节。

### 6.2 配置保存与冲突

保存用`UPDATE ... WHERE id=? AND revision=?`并在事务内验证权限。成功revision加1，可见性修改也加1；零行区分不可访问/不存在与冲突。冲突返回409，保留未保存输入，提示重新加载，不自动合并或覆盖。初始化不依赖该编辑流程。

### 6.3 提交与取消模拟

提交任务在现有全站任务锁下重新检查身份、池可见性、revision和参数，冻结完整快照。用户看到的池版本若已变化，返回确认提示，不静默启动。任务文件由服务端填owner_id、接受时限额快照、池来源和有效种子，禁止从浏览器输入读取这些可信字段。网页访问不到任务文件系统路径，任务目录服务账号私有。工作进程只运行有效的新任务格式，继续使用已接受策略，不因后续降级/退出而拒绝已有合法任务。

全站同时只有一个已接受模拟任务，不排队。锁覆盖并发提交的检查和登记，不能先查后无锁启动。全局繁忙不暴露其他用户身份；管理员也不能同时提交第二个任务。取消继续使用现有协作取消与提交保护，不保存取消后的残次历史。

### 6.4 历史重跑

历史回填对比实际配置内容而非仅版本号；有差异展示修改字段，确认后保留本次确认的revision，启动时再次检查。原池无权或已删只提示重新选池，不能拿快照作为隐藏入口直接运行。已拥有的历史快照可以查看/下载，这是原实验的内容，不因后来原池隐藏而收回。

### 6.5 删除账号

删除账号前显示删除范围并二次确认，先停止该用户任务并确认结束，才能清理任务数据及删除其私有池（含公开私有池）、实验配置、历史和Trace。公共池为系统公共资源，删除账号时保留，池ID和最初作者署名均不变，不转移给删除者。其他用户的历史快照不删除；引用已删除私有池的配置需要重新选池。不得在停止尚未确认时宣告账号删除成功。

账号删除使用现有全站任务锁串行协调：先在短事务内校验操作者和最后管理员保护，将目标标记deleting并撤销会话，拒绝其后续新操作；再请求取消目标任务，释放锁等待退出，重新持锁核实进程终止及提交结果。不得持SQLite写事务等待工作进程。

确认目标任务退出后，清理该用户已知任务目录及导出临时文件；失败时保留deleting状态并向管理员报告“未完成，可重试”，不能把用户重新放行或宣告成功。最后一个数据库事务删除私有池、实验配置、运行及Trace、会话和账号，保留公共池、作者文本和他人历史。成功后不会被旧任务文件重新导入。中断后由管理员明确重试删除，不引入通用任务恢复系统。管理员自身身份/权限在每次提交删除步骤时重验。

### 6.6 删除池与历史

删除角色池前显示池名称，并说明引用配置需要重新选池、历史与已启动任务不受影响；必须二次确认。普通用户不能看到其他用户的引用详情。不增加回收站，删除后不能从网页恢复。

角色池删除只删池，实验配置引用置空，其他实验快照不变；二次确认携带revision，内容已改变则重新确认。账号删除只能由专用服务执行，不开放通用ModelForm/原生admin直接delete；主库关联数据用同一transaction.atomic处理。历史删除复用已有机制，同时使下载的资源检查失败并清理该运行临时导出，不能清掉其他用户文件。

## 7. API契约

| 接口组 | 主要端点与行为 |
|---|---|
| 认证 | GET auth/csrf、GET auth/me；POST auth/login、auth/logout、auth/change-password、auth/activity |
| 角色池 | GET/POST pools；GET/PATCH/DELETE pools/{id}；POST pools/{id}/copy、pools/import；导出为授权下载 |
| 实验配置 | GET/POST experiment-configs；GET/PATCH/DELETE experiment-configs/{id}；导入分解析匹配、用户确认保存两步 |
| 模拟 | POST jobs（实验参数、pool_id、expected_revision）；GET jobs/busy仅布尔；GET jobs/mine找回本人任务；GET jobs/{id}；POST jobs/{id}/cancel |
| 历史 | GET runs、runs/{id}、runs/{id}/trace、runs/{id}/charts；DELETE runs/{id}；重跑先解析池并确认差异，最终仍走POST jobs |
| 管理员 | GET/POST management/users；PATCH/DELETE management/users/{id}；POST reset-password、unlock-login；全部实验配置/任务查询复用服务权限 |

表中路径统一以/api/v1/为前缀，统一尾斜杠；命名在计划中落实，不开放任意模型CRUD。客户端不能PATCH is_superuser等框架字段，只接受显式业务role并经管理员服务检查。配置修改和删除传expected_revision；拷贝新ID，导入匹配确认时再次检查池权限与revision。所有导出限定资源类型和格式，无任意路径输入。

成功返回单对象或列表`{items, total, page, page_size}`；错误统一`{error: {code, message, fields}}`，message中文、code稳定英文。400参数错误、401未登录/会话失效、403认证后无操作权或CSRF失败、404资源不可访问、409版本冲突/系统忙、429登录/资源限流、503存储暂忙。前端不得自动重试有副作用请求，网络失败时先查任务状态或提示用户核实。新建成功201，任务提交202，删除成功204。

分页默认50、最大200，Trace沿用50/100/200选项及图表窗口上限，属于呈现/资源约束，管理员也保留。JSON中的可能超过JavaScript安全整数范围的种子及管理员大计数用十进制字符串传输，序列化器严格解析；不使用Number转换后丢精度再提交，图表只转换可安全呈现的值。配置文件契约仍与第9.1节一致，API传输类型与文件类型通过适配器转换。

API v1服务本项目，不承诺第三方集成或公开注册。字段和错误以序列化器及契约测试为准，TypeScript类型显式维护并测试，不把TypeScript当运行时验证。前后端一次功能发布一起交付，不做多版本API兼容框架。

**不知道ID时找回任务：**`GET /api/v1/jobs/mine/`分页列出当前用户尚保留的任务，包括运行中及已结束任务，按accepted_at倒序、job_id作同时间排序键。管理员调用也仅返回自己的任务，不允许owner参数覆盖；空列表表示当前没有可列出的任务。每项包含job_id、accepted_at、status、phase、主抽数、轮数、trace、池名称快照和已保存时的run_id，不暴露文件路径。返回使用本章统一列表结构及分页上限；mine路由优先于动态ID匹配。

提交响应丢失时前端禁止自动重试POST，提示“提交结果未确认”，查询mine并展示最近任务供用户按时间和参数核对后进入。不能自动把最新任务当成本次提交；多标签页或相同参数存在歧义。空结果也不证明提交失败，请求可能尚在处理，应允许再次查询而非自动重发。已清理任务可查本人历史；本次不引入幂等提交、队列或永久任务档案。

## 8. 前端设计

采用React Router业务路由，路由守卫仅改善体验，不代替服务端授权。

### 8.1 页面分工

| 页面 | 功能 |
|---|---|
| 新建实验 | 加载和保存自己的实验配置、选择角色池、设置参数、启动模拟 |
| 角色池 | 查看、创建、编辑、复制、导入导出，以及权限允许的删除和公开/隐藏设置 |
| 实验结果 | 当前任务进度、停止任务、统计与Trace、按稀有度筛选折线图 |
| 历史记录 | 筛选、查看、下载、删除已完成实验；普通用户仅访问自己的记录 |
| 管理员 | 账号管理、全部用户的实验配置和任务管理，仅管理员可见 |

管理员在角色池与历史记录页面直接管理全部数据，不另外复制一套管理页面。侧栏固定显示当前账号、角色和退出按钮。不增加独立实验配置管理页面，普通用户的实验配置操作集中在新建实验页面。具体交互见下节。

明确保存才持久化，编辑控件不自动覆盖已保存配置。

### 8.2 页面交互

登录之外的四个常规页面和管理员页遵循8.1节。新建实验顶部为已有实验配置选择及保存/另存/导入导出，中部选择有权池并只读展示规则、作者、版本和角色摘要，下部参数及提交按钮；编辑池跳转角色池页面，不产生实验级规则覆盖。

角色池页面顶部筛选公共/我的/他人公开；管理员另可筛选所有私有池。列表显示名称、类型、可见性、私有池所有者、原作者及revision。只读用户仅查看、复制、导出。公共池不显示个人所有者。账号菜单支持改密；管理员页面分账号、实验配置、任务三个区域，危险操作独立二次确认，不混入模拟提交按钮。

React Router负责`/experiments/new/`、`/pools/`、`/results/`、`/history/`、`/management/`和`/accounts/login/`，保持已确认页面分工；后端业务统一在/api/v1/。React路由守卫只改善体验，不代替后端权限。参数校验由DRF Serializer调用共用校验器执行，前端TypeScript和即时校验只是辅助。409保留表单草稿并展示冲突；成功后更新返回对象及revision，不靠刷新整页。提交中禁用按钮，但服务端仍承担并发校验。不得在React effect中自动触发创建、删除或模拟提交。

### 8.3 状态与请求生命周期

前端状态分三类：认证概要放轻量Context；表单草稿/图表筛选放组件或功能状态；服务器结果按用户ID和资源ID隔离缓存。暂不引入Redux或复杂状态框架。注销/401取消请求并清除全部私有状态；换账号时丢弃旧请求返回值，避免上一账号慢响应覆盖当前页面。可用AbortController和账号会话代次校验，不能只清一次缓存。多标签页主动退出可用BroadcastChannel通知清理，仍以服务器授权为准。

### 8.4 图表、轮询与动画边界

折线图增加稀有度多选，默认全部选择，可单选或多选比较。选项与图例使用本次结果中的显示名称。保留主池、赠送池等既有筛选。

仅过滤图表展示，不重新模拟、不修改结果数据，不增加非Trace结果的逐抽数据。全不选时显示提示。

图表选择使用4/5/6内部值，标签映射不影响筛选；仅改名不改变统计或重算。改名后的标题、指标、下载列说明和保底提示一起校验。

进度默认每2秒轮询，仅活动任务继续，终态/401停止；隐藏标签页降低频率，卸载取消请求。未来动画仅表现服务端结果，不伪造进度、不重复模拟、不因播放续会话；遵守prefers-reduced-motion，提供跳过/暂停入口。当前只保留可组合组件边界，不实现动画播放器或预选动画依赖。

## 9. 导入、导出与下载

配置文件是可携带的数据，不是权限凭证；导入不得授权为管理员或其他用户。

### 9.1 文件契约

池文件外层包含format_version、id、name、original_author、rule_name、rarity_labels和pool_config。pool_config内保留现有名单、UP、五星及奖励字段；内层不再独立携带重复版本字段，由统一加载器转换成现有不可变PoolConfig。所有权和可见性是服务端字段，不由导入文件授权。

实验文件外层包含format_version、name、pool_ref（id与name）和parameters（draws、trials、initial_pity、initial_five_star_pity、seed、trace）。不嵌入可覆盖规则的rule_name，不在文件中接受owner或admin开关。CLI使用同一契约。

导入使用有大小边界的UTF-8 JSON（默认5 MiB，服务端可配；这是解析安全边界，不属于模拟数量限制），拒绝重复键、非有限数值及不支持版本。池导入总是新建UUID；输入ID仅作来源，不能覆盖已有池。实验按9.2节匹配池并要求确认重名候选。复制不复制所有者权限、ID或revision；作者文本保持原值。名称/作者以普通文本呈现，不插入未转义HTML。

### 9.2 导入匹配及作者署名

导入JSON不得直接赋予导入者管理员身份、他人的所有权或公共池编辑权。文件路径不能成为绕过权限的配置引用方式。

导入角色池默认成为导入者自己的隐藏私有池；管理员可以再复制为公共池，不能原地转换类型。实验配置导出同时携带池ID和名称，导入关联顺序如下：

1. 先按池ID查找，存在且当前用户有权使用时直接关联并展示池名称；池改名不影响ID引用。
2. ID不存在时，按名称查找有权使用的池：单个候选须询问确认，多个候选须用户选择，无候选则提示手动选择可用池。
3. ID存在但无权使用时仅提示不可用，不泄露池详情，不自动按名称替换；允许手动选择有权使用的池。
4. 关联后校验参数与池规则，通过后才可保存。不得按名称无提示自动关联，也不因导入实验配置自动创建角色池。

导出JSON携带最初作者署名，导入保留；缺少署名则采用导入者当前用户名。文件署名只作来源说明，不代表经过身份认证或拥有权限。导入后仍是导入者的隐藏私有池。

### 9.3 受控下载与大结果

所有导出使用同一Django应用中的受认证下载视图；不新增Tornado进程、不设置下载子域、不使用持有链接即授权的票据表。链接中的资源ID仅用于定位，必须携带有效登录Cookie且有权限；把链接发给其他用户不能绕过资源访问控制。

React发起Trace下载时使用指向后端下载端点的原生POST表单（带筛选和CSRF令牌），让浏览器接收附件，不使用fetch(...).blob()将大文件整体装进浏览器内存。提交前可用API预检权限和匹配条数，但最终下载仍重新校验，不能信任预检结果。后端分批写入私有临时文件，再以StreamingHttpResponse同步生成器按64 KiB发送；生成每1000条、传输每块检查会话和资源权限。错误在发送前返回中文错误页/JSON，使用独立下载标签页避免替换SPA；开始发送后撤权中断连接，不向CSV/JSON追加错误。已接收数据无法收回。

不把临时文件放在static或可直连media路径，不通过Nginx直接公开业务文件。所有路径由服务器生成，不接受用户文件路径。Content-Disposition文件名去掉路径/换行，响应no-store和no-referrer。生成完成前失败可返回中文错误；流开始后失败中断连接，页面说明需重新登录或重试。成功、断开、失败均关闭迭代器并在finally清理临时文件；有界清理仅清已确认不再使用的过期文件，不能按年龄删除正在导出的文件。磁盘不足不损坏原历史。

小配置和汇总JSON在同一授权视图内直接响应；带revision的配置导出若已变化则返回409要求重新导出，隐藏池权限即时重验。普通用户Trace下载上限1万条，管理员不设条数上限，但仍受硬件容量、会话有效期和连接中断影响。保留分页与图表窗口，不把整份Trace拼成bytes。

本次采用WSGI同步流式响应，下载占用一个请求执行单元；生产示例用至少两个请求线程并明确超时配置，使大下载时仍能访问退出/停止等控制入口，不把Web请求并发误解为允许多个模拟。进程内采用有限下载并发槽（默认一个，管理员也遵守资源保护），暂忙返回可重试提示，不新增导出任务队列。后续若实测需要更高并发，再讨论ASGI或独立下载服务，本次不提前引入。

## 10. 安全与资源限制

权限矩阵见第4章；本章规定认证、会话与资源边界，不另设一套业务角色。

### 10.1 密码存储与输入

密码交给Django的set_password/check_password及默认PBKDF2PasswordHasher处理，成本参数采用锁定框架版本的安全默认值，不自行拼装密码存储格式。所有创建、改密、重置入口统一调用验证器：最低6字符，最多1024个Unicode字符且UTF-8不超过4096字节，不裁剪空格、不强制字符组合；不启用会否定已确认6字符策略的额外默认长度要求。上限是资源保护，不是业务数量上限。未知账号使用框架同等级虚拟校验，不能把原始密码写入日志或会话。

最低6字符为用户明确选择；界面建议长密码，尤其管理员，不将6字符下限表述为公网强密码保证。

### 10.2 会话与CSRF

复用Django AuthenticationMiddleware、SessionMiddleware及authenticate/login/logout，DRF采用SessionAuthentication，默认业务API要求IsAuthenticated。SESSION_ENGINE使用数据库后端，不使用客户端签名数据会话。登录轮换会话键；会话Cookie设置HttpOnly、SameSite=Lax，公网Secure=true且要求HTTPS，本机loopback可HTTP。前端不读取会话Cookie，不在localStorage保存密码、JWT或会话令牌。每个受保护请求重新检查is_active、deleting、auth_version及过期；敏感写事务再次检查。must_change_password期间仅允许会话概要、CSRF获取、改密及退出，不能访问其他业务API。首个管理员自设密码无需再次修改，本机恢复密码需首次改密。

React启动先GET /api/v1/auth/csrf/取得CSRF令牌，再GET /api/v1/auth/me/判断会话；没有会话只展示登录页。登录POST使用显式csrf_protect的Django JSON视图调用authenticate/login，不依赖DRF对匿名请求默认不执行的CSRF检查。登录成功后重新获取轮换后的CSRF令牌。其他POST/PATCH/DELETE均发送X-CSRFToken；下载原生表单发送csrfmiddlewaretoken。CSRF令牌可保留在前端内存，不是登录凭据。

会话Cookie使正常刷新、页面跳转和同浏览器新标签页继续登录。设置浏览器会话Cookie，不提供“记住我”；安全边界是服务端30分钟闲置、12小时绝对到期及撤销校验，不能仅依赖关闭浏览器。SPA路由切换本身不触发后端页面请求，因此有效业务写入和节流活动POST更新活动；用户点击导航、编辑和操作图表才发送活动请求，不用常驻心跳。自动加载、进度轮询、动画播放和下载传输不能续闲置时间。先判断到期再更新活动，过期不能自行续期。SECRET_KEY通过环境持久配置。

注销用Django logout清当前会话及Cookie，采用POST并校验CSRF。用户名、角色、密码变化、禁用等原子增加auth_version，使所有旧会话立即在下一次请求或下载块检查时被拒绝，无需逐条扫描解码全库会话。改密后不调用保持当前会话有效的update_session_auth_hash，当前会话也退出。物理过期会话使用clearsessions清理。用户草稿不存跨账号共享localStorage；退出清理页面私有状态，私有响应Cache-Control: no-store。已发给浏览器的数据不能收回，后台任务不依赖登录会话持续存在。

闲置与绝对过期时长由服务端配置；默认值见本节，不由客户端覆盖。

### 10.3 登录失败限制与网络边界

登录账号失败计数针对规范化用户名（不存在的账号也计数），5次连续失败锁15分钟；窗口到期或成功登录清除账号失败次数。来源地址默认15分钟内20次失败限制15分钟，独立于账号限制。相同账号已锁时新尝试不无限延长锁定期。错误不区分不存在、禁用、密码错误；未知账号执行同参数虚拟校验，避免明显的用户名存在性差异。管理员/本机解锁只清账号计数，不启用账号、不清来源限制。

来源默认取REMOTE_ADDR；仅对显式可信代理采用其重写的来源头，不信任客户端X-Forwarded-For。无法得到可信来源使用共享unknown桶。启用CsrfViewMiddleware及DRF会话CSRF校验，所有有副作用的POST/PATCH/DELETE都校验，登录入口额外显式保护。GET不删除账号或修改配置。不设置全局csrf_exempt或宽松CORS；限定ALLOWED_HOSTS和CSRF_TRUSTED_ORIGINS，SECURE_PROXY_SSL_HEADER只用于可信代理。生产DEBUG=false，API错误不暴露路径、SQL或密码。

账号失败次数与时间、来源限制均由服务端配置。账号锁定到期自动解除，也可由管理员页面或本机命令解除，绝不因此启用账号或清除来源限制。

### 10.4 数量与资源限制

普通限额：每轮主抽1000万、轮数100万、主抽乘积1亿；Trace实际条数（含赠送）100万，单次明细下载1万，后两项沿用可配环境变量。管理员这些限额取None而非一个极大假数；TraceWriter、任务校验和导出共同支持None。类型、正数、规则边界及SQLite整数可表示性仍检查，seed保留现有文本存储方式。

取消业务上限不取消参数类型与合法性、规则一致性、认证授权和文件访问安全校验。不移除分页或分批读写，不将全部明细一次加载进内存，不自动增加并发。

管理员仍受机器内存、磁盘、计算能力及底层存储可表示范围约束。权限策略必须贯穿网页、任务提交及后台执行，不能只修改输入控件上限。

全站单模拟与任务锁见6.3节；下载并发资源保护见9.3节；API分页见第7章。管理员免除业务数量上限，不免除这些保护。

### 11.1 CLI及本机维护

本机CLI继续作为受操作系统权限保护的工具，不要求网页登录，不自动写入网页历史。网页任务必须绑定登录用户并统一校验权限。CLI普通业务入口不提供绕过用户权限直接修改网页记录的能力，管理员初始化等维护命令单独列出。

网页登录不能阻止拥有服务器文件访问权限的人直接读取数据库。CLI帮助、常用示例、参数解释、错误提示和管理员初始化步骤提供明确中文说明；密码输入不回显，自动化模拟不强制进入交互流程。必须询问确认的导入歧义不能在非交互执行中被默默接受，具体命令方式由实施计划落实。

以下为拟新增命令接口，当前尚不可用：


### 11.2 开发与生产部署

runserver仅用于本地API开发，也必须登录。Vite开发服务默认127.0.0.1:5173，将/api/代理到127.0.0.1:8000；浏览器只访问Vite地址，Cookie与CSRF维持同源流程。开发明确允许该精确Origin，不开通配CORS，不混用localhost和127.0.0.1。Vite版本对应Node要求在实施时锁定并写入说明。提供npm scripts dev/build/typecheck/test，所有用户操作说明与错误为中文。

生产运行`npm --prefix frontend ci`和`npm --prefix frontend run build`，Nginx/Caddy服务frontend/dist并将/api/转发Gunicorn的webapp.wsgi。业务前端不依赖collectstatic收集Vite产物；如使用Django自身静态资源才另行collectstatic。生产不运行Vite开发/preview服务器，也不需长期运行Node服务。非API页面深链接回退index.html；/api/不存在必须返回后端404，不能回退HTML。带内容摘要的assets可长期缓存，index.html不长期缓存，API私有响应no-store。前端VITE_环境变量会进入公开产物，禁止存任何密钥。

模拟进程通过Django管理命令启动，加载同一settings及数据库路径，不在HTTP请求内抽奖或理论计算，也不运行migrate。单机部署仍为静态前端＋一个后端Web服务＋按需模拟进程，不因前后端分离增加模拟并发或队列。后端配置、前端静态资源作为同一版本发布，提供本地构建与深链接验证；实际公网部署仍仅保留配置接口和文档。

### 11.3 模拟CLI契约

CLI模拟使用池绑定规则，删除独立--rule选择，未提供池或实验文件时使用新版默认池；原有显式模拟参数可以覆盖实验文件中的实验参数，但不能覆盖池规则。CLI按ID在指定池目录内查找再按名称询问；可用--pool-config显式解决引用。非交互时无法唯一按ID解析就中文报错并要求指定池，不自动接受名称候选。网页导出的ID不能当文件路径。

analyze同样读取新版池。export-trace保留为明确标注的本机只读维护工具，具备数据库文件权限即可导出，不宣称受网页登录控制；不自动写入网页历史。普通CLI无新增网页记录修改命令。帮助、错误、示例和维护风险说明中文化，结构化JSON字段保持稳定英文键。

### 11.4 新格式切换与清理

**开发过渡边界：**稳定旧版本留在原工作目录，使用原虚拟环境、旧Streamlit入口、v4数据库及旧任务目录；不得把新分支代码或新依赖安装进旧环境。新版本在独立工作树和独立虚拟环境开发，使用显式指定的临时v5库、任务及导出目录，禁止复用真实data、符号链接指向旧数据或继承指向真实库的环境变量。两套本地服务如同时使用必须使用不同端口；测试的新模拟采用小规模输入，不干扰旧任务。

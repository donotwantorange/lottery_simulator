# 多轮 Trace 与实验界面重组详细设计

## 1. 状态与范围

本设计已获用户确认，尚未实现。用户确认网页Trace100万条、单次下载1万条，限制集中配置。已据此整理[实施计划](2026-09-20-multi-trial-trace-ui-plan.md)；本次仅更新规划文档，不修改程序或清理历史。基于已合并的概率核心重构，现有未提交文档补充保留。

已确认需求：仅开启 Trace 时保存逐抽结果，允许多轮；整理页面布局；展示按每轮主池抽次统计的四、五、六星轮数；允许清空旧历史并直接启用新数据库，不做迁移。

本设计推荐值：网页每次 Trace 最多 1,000,000 条实际记录，写入批次 1,000 条，明细默认每页100条、可选50/100/200；网页单次明细下载最多10,000条。这些是可集中修改的产品限制，不是经性能测试证明的容量承诺。

保留抽奖规则、初始参数语义、赠送子规则、两阶段抽样、理论计算、认证和单任务运行约束。不增加断点续算、部分实验分析、实时逐抽查看、四五星编辑表、四五星角色批量汇总、通用插件或性能框架。

## 2. 方案选择与整体结构

三个备选：全部明细留内存（改动少，但多轮扩大内存和页面负担）；直接向历史分批写半成品（需要历史状态、清理与发布隔离）；先写任务临时库，完成后事务导入历史（多一份短期磁盘数据，完成时有导入成本，但完整历史边界清楚）。本设计选择第三种。

```text
新建实验 → 参数/配置快照 → JobManager → worker
                                         ├─ simulate → 汇总结果
                                         └─ record_sink → trace.sqlite3 分批暂存
                                                        ↓ 成功完成
                                      history_v4.sqlite3 单事务导入
                                                        ↓
                         实验结果 / 历史记录 → 分页查询、按抽次聚合
```

核心不依赖SQLite或Streamlit。统一单抽接口和概率执行器保持原样；simulate只新增记录输出通道和轮次标识。网页不用完整records数组渲染页面。

## 3. 序号与状态契约

所有用户可见序号从1开始，计数/保底进度仍从0开始。

| 字段 | 定义 |
|---|---|
| trial_index | 实验轮次，1～trials |
| draw_index | 本轮所有实际抽取的顺序，包含赠送；每轮从1重置 |
| source | main或bonus |
| source_index | 本轮当前来源的抽次；主池1～draws，赠送按本轮所有赠送抽连续累计 |
| bonus_event | 主池为null；赠送为子规则事件名称 |
| main_draws_completed | 本轮历史初值加已完成主抽；赠送不增加 |
| draw_result | 原单抽结构：outcome、probabilities、state_before、state_after |
| main_state_before/after | 主池抽前后双保底状态；赠送两者相等 |

记录唯一身份为 `(trial_index, draw_index)`；历史唯一键再加run_id。删除“draw_index是整次实验全局序号”的潜在含义，不新增冗余全局序号。网页表头明确写“轮内总抽次”。

例：初始累计29，每轮主抽2次。每轮记录顺序为：主抽1(draw_index=1，累计30)、赠送1～10(draw_index=2～11，累计30)、主抽2(draw_index=12，累计31)。第2轮从draw_index=1重新开始。

每轮从相同初始双保底状态和累计主抽初值开始；赠送领取状态不跨轮沿用。初值≥30时该轮不再领取首30赠送。赠送临时池独立初始化、继承名单/奖励，并保持原固定六星概率与五星小保底。

## 4. 核心记录输出与随机性

保留 `collect_records=False`；移除trials必须1的限制，新增可选 `record_sink: Callable[[DrawRecord], None]`。

| 调用方式 | 行为 |
|---|---|
| collect_records=False，sink=None | 不创建DrawRecord，返回汇总 |
| collect_records=True，sink=None | 内存收集，返回records；供小规模Python调用和既有CLI接口 |
| collect_records=True，有sink | 每条记录按轮次/轮内顺序交给sink，返回records空tuple与实际record_count |
| collect_records=False，有sink | 参数错误，禁止含糊地丢弃或暗中开启记录 |

SimulationResult新增trace_enabled、record_count；records为空不能再用来判断Trace是否启用。网页汇总序列化始终排除records，CLI内存模式开启时可附records。record_count关闭时为0，开启时为已完成实验的实际记录数。sink异常中止模拟并向调用者传播，不返回看似完整的结果。

每次simulate只创建一个rng，跨轮推进；不按轮重复seed。sink、批次大小、分页、导出不消耗随机数；记录必须在后续状态变化前构造，传给sink后不修改。保持sampling_version=1的前提是抽样顺序及roll消耗确实不变，并以受控roll和Trace开关对照验证。变化时才升级sampling_version，不能为方便保留错误版本。

核心/CLI不新增网页总记录数硬上限，内存模式的容量风险在CLI帮助和文档说明。网页明确使用sink，不能意外退回内存收集。进度仍按已完成主抽/总主抽展示，同时显示“写入明细/保存历史”；主抽到100%不代表整个任务完成。

## 5. 网页容量校验

默认上限 `MAX_TRACE_RECORDS=1_000_000`，按实际主抽加赠送计算，替代旧“单轮主抽最多10万”限制。既有非Trace工作量上限继续生效。

对当前规则，设每轮主抽D、轮数T、初始累计H：当H<30且H+D≥30时每轮赠送B=10，否则B=0；记录总数N=T×(D+B)。例如D=30、T=25,000、H=0时恰好100万，允许；多一轮拒绝。

估算复用赠送事件定义：在规则层提供纯计算的每轮预计赠送抽数接口，由当前FirstThirtyBonusRule实现；引擎、网页和worker引用同一口径，不在各层复制30/10常量。未来无法提前确定数量的子规则必须明确拒绝网页Trace准入，直到提供安全上界，不按平均值估算。

网页启动前与worker执行前均校验；sink累计计数还有运行时上限防线。溢出立即失败，不截断Trace。显示实际记录数，不给未经测量的精确MB或耗时承诺。

## 6. 任务暂存与完整性

新任务根 `data/jobs_v4/<job_id>/`：parameters.json、state.json、result.json（仅汇总）、trace.sqlite3（仅Trace）、cancel.request、worker.log。暂存库表结构与历史明细的可查询字段一致，可不带run_id；带自身格式版本及完整性元数据。

worker按1000条批量提交暂存SQLite，最后不足一批也必须flush。Trace未结束时仅worker可用该库，网页不开放部分明细。

完成流程：

1. simulate完成，flush并关闭暂存写连接；校验记录总数、轮次边界、每轮主抽数、来源计数及唯一键，无缺号/重复。每条入库时校验版本、状态和索引字段与JSON一致。
2. 原子写汇总result.json（不包含records）；保存阶段显示明确状态。
3. HistoryRepository单事务写运行汇总并以有界批次读取暂存库插入明细；不是把所有records重新装入列表。最后核对总数后提交；失败完整回滚。
4. 使用job_id作为固定run_id，保存成功后在state中写run_id和history_saved=true，再标记completed。重复完成请求不得重复历史；已存在同ID只在对应同一任务快照时视为已保存，否则报错。
5. 成功后删除该任务暂存库及已确认伴随文件，避免永久保存两份明细；删除失败记录告警，历史仍可用。

汇总result.json包含trace_enabled、record_count和版本信息；它不是可单独恢复全部Trace的备份。state包含history_saved/run_id，不能仅凭result.json存在认定历史已入库。

历史保存失败：保持已完成计算结果和完整暂存Trace，state为completed且标明persistence_error/history_saved=false；当前结果页可用暂存库分页查看及导出，但历史列表不出现。第一版不增加自动重试/恢复按钮，保留文件用于诊断，不在新任务启动时删除这个已完成结果。

取消/计算失败：不保存完整历史、不展示部分Trace；关闭连接后清理该任务暂存库与部分结果，保留参数、状态和日志。暂存写入失败视为计算失败，不能降级成无Trace成功。

取消在完成发布前生效：已有取消标记则不导入；导入期间按批检查取消并回滚。最终提交与取消受同一任务锁保护，提交成功即完成边界，之后停止操作返回已完成而不删除历史。

崩溃恢复：先按现有进程归属检查停止有效新任务worker，再检查历史中是否已有该job_id。已存在且完整则修复completed状态；否则将未完成任务置失败、清理半成品。版本错误文件不用于kill；旧jobs不扫描。历史删除后不从残留job重新导入或回退暂存展示：history_saved=true时历史是唯一数据来源。

## 7. 新历史数据库与查询

本地默认 `history_v4.sqlite3`，容器默认 `/app/data/lottery_v4.sqlite3`。自定义LOTTERY_DB_PATH仍优先，指向旧库时安全拒绝，不自动覆写。

仍用两张表，不建角色或概率字典表：

- simulation_runs：现有参数/配置/汇总字段，增加record_count；仅完整运行可见，id=job_id。summary JSON无records。
- draw_records：run_id、trial_index、draw_index、source、source_index、rarity、character_name、record_json；主键(run_id,trial_index,draw_index)，外键级联删除。

字符身份仍为(星级,名称)；名称可跨星级相同。没有名单时SQL为NULL，UI显示“未配置角色名单”。不在SQL存翻译后的中文列。

额外建立(run_id,source,source_index,rarity)索引服务位置统计。其他筛选先利用run/轮次范围与现有索引，不为每个筛选预建组合索引；没有性能证据不扩大索引集合。

接口职责：get_run只读汇总，移除include_records全量查询；query_records返回分页记录与匹配总数；iter_records供分批导出；position_counts负责位置聚合。历史和完整暂存库使用同一筛选定义与返回结构，可通过小型TraceReader接口共用查询逻辑，不让UI知道SQL。

筛选支持轮次或轮次范围、来源、星级、角色（同时携带星级）、来源抽次范围。明细默认第1轮、全部来源，按trial_index/draw_index升序；提供“全部轮次”明确选择。limit允许50/100/200，offset从0开始；查询参数严格验证并SQL绑定。切换运行或筛选重置页码，删除导致空页时回到合法页。

## 8. 按抽次统计的准确口径

默认来源为主池。横轴source_index表示“本轮第几次主池抽取”，范围1～D，允许超过80；不加初始H，不用draw_index，不按保底重置。

纵轴计数 C(i,r) = 在所选轮次中，第i次主抽结果为星级r的轮数。比例=C(i,r)/该位置实际观察轮数；默认所有完成轮次时分母T。每个主抽位置C(i,4)+C(i,5)+C(i,6)=T。不存在位置不能当成观测到0星，分母为0时显示“无数据”。

主池和赠送独立切换，无“合并来源”位置图。赠送横轴为本轮赠送来源抽次；未触发赠送时显示无数据。支持轮次范围和抽次区间；不应用明细页星级/角色筛选到分母，以免把条件筛选比例误标为全体概率。

三条星级折线或堆叠柱展示轮数/比例，配套表格。默认显示前200个位置，每次图表最多1000个位置；可选择连续区间，不能静默抽样或把不同位置合并。SQL先筛区间再GROUP BY，不将全量明细拉到Python。样本比例明确标“模拟频率”，不称为当抽条件概率。

关闭Trace时该页提示本次未保存逐抽结果，无法补算位置频数，不自动重新模拟。规则的1～80保底概率曲线仅在规则预览展示，不与位置频数图叠加为同一口径。

## 9. 页面与交互布局

保持Streamlit与现有认证。侧栏只放一级导航、全局任务状态和必要账户操作；主要参数移到新建实验主区。使用一个app入口分派视图，避免为导航增加外部前端或API服务。

```text
侧栏                   主区
新建实验               [模拟参数] [奖池与规则]
实验结果               参数/容量预览 → 开始模拟
历史记录
当前任务状态           结果：[概览] [分类统计] [按抽次分析] [逐抽明细]
```

### 新建实验

模拟参数：每轮主池抽数、实验轮数、原命名“假设主池已累计多少抽仍未出6星”、种子、Trace开关（默认关闭，多轮可用）；高级设置保留初始五星进度。

奖池与规则：UP份额、六星名单与权重、五星概率与保底、奖励表、JSON导入/导出/恢复默认；显示四五星名单数量并注明通过JSON编辑。主池保底概率预览放此页，轴名“连续未出六星后的下一抽位置”，说明第65/66/80边界及五星状态影响。

启动预览同时显示每轮主抽/赠送/总抽、实验总主抽/总赠送/总实际抽数、是否Trace及预计记录数。非法输入就地提示。开始后冻结任务快照并跳转实验结果；运行中可编辑下一次草稿，但不能启动第二个任务。切页不丢草稿，保留当前data_editor稳定基线修复。

### 实验结果

顶栏固定：当前选中实验ID、来源（当前任务/历史）、状态、Trace、参数快照入口、复用入口。全局活动任务提示与选中历史独立，后台任务存在时不强制把用户正在看的历史替换掉。

运行状态展示轮次/主抽进度、耗时和停止按钮；保存阶段保留进度提示。完成后展示四个视图，仅渲染选中的视图，不能因普通tabs机制提前执行全部明细SQL。

| 结果视图 | 内容和范围 |
|---|---|
| 实验概览 | 参数与配置快照、每轮/实验总抽数、主要六星指标、理论对照、运行版本信息；不放规则曲线 |
| 分类统计 | 星级、六星构成、六星具体角色、奖励、保底五个二级选项；保留已有图表和数值表，主/赠送/总计切换仅作用这里 |
| 按抽次分析 | 上一节定义的主池/赠送位置频数、轮次范围、抽次区间与计数/比例 |
| 逐抽明细 | 轮次、来源、星级、角色、抽次筛选，匹配数、分页、完整中文Trace列及下载 |

逐抽表优先列：轮次、轮内总抽次、来源、来源抽次、星级、角色；后续列保留主池累计数、UP/限定、概率、主/来源池抽前后双保底、奖励和触发。基础列默认展示，完整状态列可切换；JSON导出始终完整，不因隐藏列丢字段。

### 历史记录

保留规则、Trace、UTC日期筛选及分页；列表增加记录总数。选单条“查看结果”跳转结果页；“复用参数”回到新建实验恢复完整配置、轮数、种子、初始状态和Trace，但不自动运行。

保留最多两条对比：只对比汇总、配置与分类统计，不一次展开两份明细。版本/规则不一致给出警示。删除需明确二次确认，级联清理对应明细并清理当前选择/分页/导出缓存；不通过旧job文件复活记录。

session只保存草稿、导航、job_id/run_id与筛选分页，不保存完整records或数据库连接。选中运行消失后提示失效；认证仍先于所有读库、查询、导出与删除操作。

## 10. 导出及CLI

网页提供“汇总JSON”（参数、配置、版本和统计，无records）与“明细JSONL”两个明确入口。JSONL首行是type=metadata的运行快照与筛选范围，其后每行type=record含完整嵌套记录。排序与明细查询一致。

为避免Streamlit下载缓冲重新制造全量内存问题，首版网页单次明细导出上限10,000条；点击准备下载后先查匹配数，超出提示缩小轮次/抽次范围，不截断也不静默改筛选。普通分页不生成下载文件。内存只承载限定大小下载，不宣称端到端HTTP流式传输。

完整大结果可通过项目本地导出命令导出已保存历史：`python -m lottery_simulator export-trace --database PATH --run-id ID --output FILE`，内部批量读取，输出相同JSONL；默认禁止覆盖已存在目标。命令明确由应用导出模块访问HistoryRepository，抽取核心不导入dashboard。临时输出成功后原子替换；失败清理自己创建的临时文件，不覆盖配置/源库路径。

原simulate --trace解除单轮限制：text增加轮次列，json包含带trial_index的records；维持内存模式便于小实验，帮助提示大Trace建议使用网页落库后本地导出。新增导出命令不运行模拟、不消耗随机数。CLI仍不自动保存到网页历史。

## 11. 版本、文件切换和清理

| 标识 | 新值 | 原因 |
|---|---|---|
| rule_version | 字符串2.0 | 规则数学行为不变 |
| config format_version | 整数1 | 名单配置结构不变 |
| sampling_version | 整数1，须验证 | 随机数顺序不变 |
| record_format_version | 整数2 | 新增轮次、明确序号语义 |
| result_format_version | 整数2 | 明细与汇总拆分、记录元数据 |
| job_format_version | 整数2 | 暂存/历史引用与发布状态 |
| database schema/user_version | 整数4 | 多轮主键及查询字段 |
| trace暂存库格式 | 整数1 | 新文件类型独立校验 |
| JSONL导出格式 | 整数1 | metadata/record行协议 |

所有整数版本拒绝bool，必需字段缺失拒绝。旧记录不补trial_index=1，旧result不兼容读取。新历史和任务目录、Compose、Dockerfile、systemd备份源/文件名前缀、文档成套改v4；自定义外部路径需核对归属。

## 12. 模块改动边界与验收

| 模块 | 调整 |

| engine / formats / rules子规则接口 | 多轮记录、sink、记录数、版本、纯赠送数量预估 |

| 当前手册 / 部署静态文件 | 容量口径、下载边界、v4路径与清理记录 |

验收必须包含：

1. 至少3轮、初始29、主抽2：每轮12记录，总36；每轮仅10赠送，主池状态隔离，轮次/来源序号连续。
2. 同种子同配置：Trace关闭、内存、sink及不同批次得到相同汇总和逐抽序列；关闭时不创建记录。
3. 主池第65/66/79/80边界、双保底、角色与奖励回归；多轮不重置rng到相同seed。
4. 精确100万允许，超1条拒绝；赠送计入上限；worker重新校验，运行时sink不得静默截断。
5. 批次尾部flush、重复键/缺轮/缺号/字段不一致拒绝；导入中途失败无半份历史，第二次保存不重复。
6. 取消发生在计算、flush、导入、提交前后各窗口；进程被中断后能区分已提交历史与半成品。无效版本/PID不驱动kill。
7. 保存失败仍能从完整暂存读取当前结果，历史不可见；成功后历史删除不从job复活。
8. 人工可算位置矩阵验证轮数和比例、分母、抽次范围、赠送隔离及跨80位置；零观测不除零。
9. 分页/筛选/角色同名/空名单/删除/JSONL顺序与完整字段正确；网页明细和图表不调用全量records读取。
10. 新建草稿切页不丢、连续单元格编辑有效、多轮Trace可开、历史复用保留Trace；运行中看历史不被强制切换。
11. 小规模真实浏览器验收页面导航、图表、明细分页、下载、复用和删除；工具不可用则记录未验，AppTest不能替代视觉验收。
12. 既有适用测试与新增功能测试通过；只验证功能，不加SHA或性能框架。分批只限制Trace内存，现有汇总分布本身仍会随实验取值规模增长，不承诺总内存恒定。

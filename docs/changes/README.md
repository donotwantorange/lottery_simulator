## 统一记录规则

| 改动规模 | 文档要求 |
|---|---|
| 小修改：文档、简单修复、少量参数调整 | 一份 `YYYY-MM-DD-主题.md`，包含方案、步骤及验证结果 |
| 较大修改：新功能、结构重构、多模块改动 | 同主题的 `-design.md`、`-plan.md`、实施记录 `.md`，随阶段推进创建，不提前生成空文件 |
| 合并 | 在实施记录中追加；涉及多项改动或复杂冲突时可另建 `-local-merge.md` 并关联 |

### 状态与证据

统一状态为：待确认 → 已确认 → 实施中 → 已验证 → 已合并。仅记录实际到达的阶段；暂停或阻塞作为附注，不伪装成完成。不需要合并的文档工作可以停留在已验证。

- 已验证：约定的本次验收通过，同时列出范围外或尚未完成的检查；如仍缺少本次必需验收，不标为已验证。
- 已合并：已完成本地集成，不等于在线推送或实际部署。
- Git状态单独记录：是否提交、提交号、合并目标及合并号、是否推送。不适用或尚未执行时明确写明，不编造编号。
- 记录规则不构成修改、提交、合并、推送、部署或删除数据的授权。

每项记录应明确：当前状态、目的、确认方案、范围及不做什么、涉及文件、实施步骤或关联计划、实际验证结果、未验事项、Git状态。较大改动以实施记录汇总最新进度，设计和计划互相链接，避免在多份文件重复维护完整过程。

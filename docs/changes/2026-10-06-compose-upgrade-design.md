# Compose交互式升级设计

- 日期：2026-10-06；用户要求在旧安装脚本加入升级功能并更新文档。
- 基准：本地master `7ea72c9`；本轮不推送、不连接服务器、不修改真实库或原本地使用手册。
- [实施计划](2026-10-06-compose-upgrade-plan.md) · [实施记录](2026-10-06-compose-upgrade.md)。

## 入口与范围

`bash scripts/install.sh`保持首次安装，拒绝已有数据；`bash scripts/install.sh --upgrade`升级已经运行的标准app/Caddy Compose项目。沿用现有构建、网络预检、迁移和启动段落；升级准备/收尾在被source的`upgrade.sh`，旧数据探针在`upgrade_probe.py`。不安装新依赖，不自动Git拉取、重置密钥、重置管理员、删除卷或自动恢复数据库。

升级使用操作者已经取得的完整新版项目。目录、Compose项目名、`.env`和卷名保持不变；Git/ZIP获取新版由操作者完成，避免执行中的脚本被自动拉取替换。仅支持服务器同机的标准Docker Unix socket（拒绝远程/rootless上下文），实际容器环境为标准v5/v6路径、命名数据/备份/证书卷，以及本目录前端挂载的部署；停止、部分安装、额外服务/挂载、host网络或app宿主端口配置须手动处理。

## 识别与维护边界

1. 先核对新Compose配置及旧app/Caddy的项目/目录标签、健康状态、旧镜像ID、实际环境和挂载；不能根据新版Compose中的v6路径猜旧库版本。
2. v5须确认只迁账号的范围，所有升级均须确认维护。先暂停已安装备份timer，确认备份service未活动，再停止Caddy入口。
3. 在旧app内使用旧镜像自己的JobState验证器检查目录/状态，拒绝活动worker、未知条目、缺失/损坏状态、危险链接和未完成账号删除。规范UUID任务不忽略；v5不能用新v6解析器代替旧解析器。
4. 再暂停旧app，在无网络的旧镜像辅助容器中读取冻结数据并重新检查，避免晚到请求在检查后启动worker。数据卷只读、备份卷可写，辅助容器最多运行600秒。失败只清理由CID文件记录的本次辅助容器并解除本次app暂停，Caddy与timer保持维护状态。

使用Docker原生[容器暂停](https://docs.docker.com/reference/cli/docker/container/pause/)及[强制移除](https://docs.docker.com/reference/cli/docker/container/rm/)；只有冻结状态再次确认无活动任务且备份齐全后，才移除旧app容器。容器移除不带卷删除参数；不用共享任务缓存、维护服务或自建备份协议。

## 备份、迁移与网络

- 复用旧项目已有的`backup_db.backup_database`接口，SQLite只读来源、在线快照及完整性检查；主机复制后再次完整性检查。
- 新快照放原备份卷的独立目录；主机备份在`/var/backups/lottery/<项目>/upgrade-<时间>-<随机值>`，目录0700、文件仅所有者访问。保留数据目录、旧前端、环境文件、旧容器inspect和新Compose解析配置；inspect/config包含密钥，不输出原文、不提交Git。
- 备份完成后移除已检查的旧app，再`compose down`移除本项目服务/网络，保留数据、备份和证书卷。执行现有网络预检后才构建，冲突/读取失败均停止，不删除其它项目资源。
- v6直接执行migrate，保留账号与业务，不重新初始化管理员或默认业务。
- v5要求没有已有v6目标库或非空目标任务/导出；空v6 migrate → 从原备份卷中的快照执行import_v5_accounts → init_business_defaults。来源完整结构和目标空库由现有账号转移服务再次严格校验。
- v5只迁账号和登录限制，auth_version递增；旧池、配置、历史、Trace与会话不迁。旧v5库与目录留在原卷及备份中，不原地迁移、改名、清理或自动覆盖。

## 启动、验收与失败

`compose up -d --wait --wait-timeout 120`确认启动/健康，随后仍需操作者验证原账号、连续实验、Trace、取消、可信公网HTTPS和备份。健康不等于业务或证书验收。

已有备份unit可能被管理员定制；本轮不自动覆盖。部署文档给出标准unit更新命令，自定义目录/参数须对照保留。timer保持暂停，只有业务及备份验证通过后才由操作者恢复；没有timer则不新建。

失败报告阶段和备份路径，保留旧数据与错误现场。不自动重启入口、回滚镜像、覆盖数据库或续跑v5导入。旧app尚在时可核实后恢复原容器；已移除时按已记录旧版本、旧镜像和备份手动恢复，先保存当前数据，禁止down -v和reset --hard。

## 验证范围

沿用unittest/PTY假Docker执行首次安装与升级分支，真实临时SQLite/JobState检查数据拒绝边界；另从旧提交建立临时v5源码/库，验证旧任务解析器。Docker原生暂停、暂停时复制、移除仅使用独立无网络/无卷测试容器。整机服务器升级、镜像下载、正式证书和实际systemd备份unit更新另由部署者验收，不用模拟结果替代。

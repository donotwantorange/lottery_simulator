# 稀有度规则扩展与网页显示优化实施计划

> **执行要求：** 按任务顺序串行推进；每项任务完成后核对其交付判据，再进入下一项。实现前端时遵守 `docs/standards/ui-interaction.md`，涉及权限、快照或资源归属时遵守 `docs/standards/permissions.md`，不修改抽样器、随机数消耗、理论公式或抽样版本。

**目标：** 在不改变现有计算核心的前提下，加入可在网页中使用的 `mrfz` 公共规则，统一软保底参数的用户表述，修复实验预览统计错位，并将默认角色池显示名更新为“zmd默认角色池”。

**架构：** `mrfz`以新的规则JSON和公共数据库规则对象提供，初始化命令负责幂等创建；默认角色池继续绑定`zmd`，只更新其显示名称。软保底采用前端显示层的 `N ↔ soft_start` 转换，后端和Python计算仍使用原字段。网页通过共用格式化函数生成规则说明，预览卡片使用独立标题和固定统计行。

**技术栈：** Python 规则定义与Django服务、SQLite业务库、React＋TypeScript网页、现有JSON配置与测试工具。

**依据设计：** [2026-10-10-rarity-rule-and-display-design.md](2026-10-10-rarity-rule-and-display-design.md)。

**实施进度（2026-10-12）：** 任务1—6实现与本地可执行验收完成；桌面/390px/等效640px布局通过，原生200%受工具限制未直接验；任务7集成中。验证与实际边界见[实施记录](2026-10-10-rarity-rule-and-display.md)。

## 全局约束

- `mrfz`基础概率固定为3星40%、4星50%、5星8%、6星2%，合计100%。
- `mrfz`仅启用六星软保底：连续50次未获得6星后，从第51抽起每抽增加2个百分点；不增加硬保底、赠送池、大保底或周期赠送。
- 用户界面填写连续未获得次数N，保存仍使用现有 `soft_start = N + 1`；增幅界面使用百分点，保存仍使用小数比例。
- 默认池的新显示名为“zmd默认角色池”；池ID、规则ID、历史快照和抽样结果不改写。
- 公共规则和公共池只能由管理员维护；私有资源的现有权限、公开/隐藏和署名规则不变。
- 本轮不增加数据库表、不引入迁移框架、不改概率计算、随机数消耗或历史重算。

## 文件与模块边界

- `configs/rules/mrfz.json`：新的可导入/初始化规则定义。
- `configs/pools/default.json`：默认池显示名更新；池结构和引用不变。
- `dashboard/management/commands/init_business_defaults.py`：幂等创建`mrfz`公共规则，并按稳定ID更新默认池显示名；冲突时拒绝覆盖。
- `lottery_simulator/config_documents.py`、`scripts/install.sh`、相关安装/配置测试：纳入新的规则文件，保留`zmd`作为默认规则模板。
- `frontend/src/formatters.ts`（必要时新增）：统一软保底文案、百分点格式和中文状态映射。
- `frontend/src/components/RuleEditor.tsx`、`RuleReadOnly`及规则/池/实验相关页面：接入N与内部起点转换和共用说明。
- `frontend/src/pages/NewExperiment.tsx`、`SimulationPreview.tsx`及样式文件：修复“每轮/全部轮次”统计卡片布局。
- 受影响的前端、后端和配置测试，以及本主题实施记录：只覆盖本轮行为，不重写无关历史测试。

## Review Focus

1. `mrfz`配置与数据库初始化不能只存在于文件中，网页规则列表必须能看到并选中它。
2. 软保底文案中的50/65是“连续未获得次数”，不能误存为内部起点或把真实初始保底计数减一。
3. 关闭软保底、非最高稀有度、赠送池和无权限查看时，说明和字段必须符合当前适用状态。
4. 默认池改名不能改池ID、历史快照或其他同名资源，当前数据库已有旧名时不能无条件覆盖。
5. 预览统计卡片必须保持数字和标签成行，在桌面、约390px和200%缩放下不再错位。

### 任务1：新增mrfz规则配置与初始化边界

**依赖：** 无。

**涉及文件：** `configs/rules/mrfz.json`、`dashboard/management/commands/init_business_defaults.py`、`lottery_simulator/config_documents.py`、`scripts/install.sh`、`tests/test_config_documents.py`、`tests/web/test_bootstrap.py`及相关安装文件清单测试。

- 创建稳定ID的`mrfz.json`，四档稀有度按rank排列，概率与软保底参数按设计填写；其余机制明确关闭或使用现有合法空值。
- 扩展初始化命令：在管理员、数据库版本和默认资源前置检查通过后，幂等创建`mrfz`公共规则；已有同ID且内容合法时不覆盖用户修订，名称/ID冲突时停止并报告。
- 默认池仍只绑定`zmd`；对已存在的固定默认池按稳定池ID处理名称更新：仅当对象仍是项目公共默认池且旧名为“默认角色池”时改为“zmd默认角色池”，不修改任何实验/历史快照；其他状态或同名冲突拒绝覆盖。
- 安装脚本、配置清单和测试夹具纳入`mrfz.json`，但默认CLI规则路径仍为`zmd.json`。
- 验收：在隔离数据库执行初始化两次，两个公共规则可读取、默认池绑定zmd且新名正确；第三方同名或错误ID不会被覆盖。

### 任务2：共用软保底参数转换与说明格式化

**依赖：** 任务1。

**涉及文件：** `frontend/src/formatters.ts`（新增或扩展）、`frontend/src/components/RuleEditor.tsx`、`frontend/src/components/RuleReadOnly.tsx`、`frontend/src/api/types.ts`及相关组件测试。

- 提供稳定的读写转换：读取显示`soft_start - 1`，保存把合法N转换为`N + 1`；增幅在界面显示百分点，保存除以100。转换拒绝bool、负数、非安全整数和超出现有服务端约束的值。
- 提供按稀有度、启用状态、主池/赠送池生成说明的函数：最高档使用“连续N次没有获取本档”，非最高档使用“本档或更高”；关闭时只显示“软保底未启用”；增幅显示四位小数并使用“百分点”。
- 保留原始输入文本、最近合法值和错误，收起控件不能丢失错误；清空或非法输入不能静默变成0。读写JSON时继续使用内部字段语义。
- 验收：zmd显示65并保存66，mrfz显示50并保存51；关闭/重新开启保留值；非法输入可见且阻止保存；赠送池说明不冒充主池。

### 任务3：规则页、池摘要和实验说明统一接入

**依赖：** 任务2。

**涉及文件：** `frontend/src/pages/Rules.tsx`、`frontend/src/pages/Pools.tsx`、`frontend/src/pages/NewExperiment.tsx`、`frontend/src/components/RuleSummary.tsx`及结果/Trace中已有保底说明组件或格式化调用点。

- 删除各页面直接拼接的旧“65/5%/6星”文案，统一调用任务2格式化函数；同步规则编辑、只读摘要、池摘要、新建实验、初始条件、结果/Trace和相关帮助文字。
- 保持稀有度使用稳定ID，显示名可修改；名称含“干员”时不重复追加，概率约束说明使用“百分点”。
- 规则列表和规则选择能够显示并选择初始化后的`mrfz`；新建规则仍以zmd结构作为编辑模板，不把mrfz硬编码成唯一规则。
- 验收：修改软保底起点、增幅或稀有度名称后所有受影响位置同步；无权限查看只读；关闭机制后不显示生效句式；zmd默认池新显示名在新选择和摘要中正确出现。

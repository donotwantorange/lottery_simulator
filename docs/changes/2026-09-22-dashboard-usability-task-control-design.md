# 网页使用体验与任务控制改进设计

日期：2026-09-22。

状态：设计已实施，实际验证与未验边界见[实施记录](2026-09-22-dashboard-usability-task-control.md)；本文保留原设计范围，不修改已有历史数据。

关联：[当前页面说明](../dashboard-guide.md)、[本地使用手册](../local-usage.md)、[多轮Trace本地合并记录](2026-09-22-multi-trial-trace-ui-local-merge.md)、[操作文档校对记录](2026-09-22-operation-docs-audit.md)。

## 1. 目标与范围

本次解决三类问题：

1. 简化概览表格，直观显示实验轮数和每轮／全实验规模。
2. 让进度与实际阶段一致，并使后续耗时阶段也能响应停止。
3. 整理现有页面布局，分类统计使用理论与模拟并排柱及清晰数值标签。

面向个人使用的中文桌面网页，主要使用键盘和鼠标；兼顾窄窗口。继续使用现有Streamlit和“新建实验／实验结果／历史记录”三页面，不更换框架，不建设额外的设计系统，不增加无关依赖。

不改变抽奖规则、概率公式、种子抽样顺序、统计口径和逐抽数据内容；不改变v4历史数据库格式，不清空历史。现有Trace默认关闭、网页记录与下载上限保持不变。

不包含模板、标签、批量删除、任务队列、并发扩展、断点续算、取消数据恢复、保存失败重试、置信区间、服务器现场部署或独立性能框架。

## 2. 现状与设计原则

源码检查已确认：概览按轮数生成重复抽数行；任务进度主要按主抽计数；理论计算没有完整接入取消检查；参数与明细筛选较多纵向堆叠；历史查看按钮重复携带长UUID。

用户反馈：分类柱状图的理论值与模拟值不便比较，需要直接并排及数值标识。本次明确图形契约，不依赖图表组件的默认排列方式。

当前尚未进行真实浏览器视觉审查；不将颜色对比度、实际间距、键盘和窄屏问题声明为已复现缺陷。

原则：重要信息优先，相关操作集中，次要信息折叠；优先使用已有控件、查询和数据；仅查询所选结果视图，不因布局改变而加载全部Trace。

## 3. 页面组织

### 3.1 侧栏

保留三个页面导航和全局活动任务摘要、停止操作。用户查看历史时仍能看到当前任务运行状态，但不自动覆盖正在查看的历史结果。

### 3.2 新建实验

桌面宽窗口中，上方采用主要参数区与较窄运行摘要区；下方奖池表格等使用全宽。窄窗口按参数、运行摘要、详细配置的顺序上下排列，不以固定像素宽度强制两栏。

- “主池抽数”与“实验轮数”并排，旁边明确主抽按每轮计。
- 保留完整名称“假设主池已累计多少抽仍未出6星”，单独占行并保留帮助说明。
- 随机种子仍可留空；Trace标签显示“保存逐抽明细（Trace）”，说明主抽和赠送均计入。
- 运行摘要展示每轮主抽／赠送／总抽、实验轮数、全实验总抽及预计Trace记录数；“开始模拟”集中在该区域。
- 奖池与奖励设置、高级设置、主池规则预览保留为下方折叠区域；四、五星名单仍通过JSON编辑。
- 只有一种规则时弱化规则选择的视觉优先级，不删除规则参数或改变默认规则。
- 错误显示在相关设置附近，启动区域同时说明无法运行的原因；已有任务时不可再启动第二个任务。

继续保留页面切换草稿、配置导入导出和历史复用逻辑。运行参数是启动时的不可变快照，之后编辑不影响当前任务。浏览器刷新不作为草稿持久化手段。

### 3.3 实验结果公共区域

顶部依次显示结果身份、规模摘要、保存状态和常用操作。示例：

> 每轮主抽100次 × 实验10,000轮\
> 每轮赠送10次 · 全实验共1,100,000抽

这些数字取自所选结果快照，不取当前新建草稿。运行ID可以缩略展示，完整值仍可查看与复制。

“复用参数”“下载汇总JSON”集中放置；“参数与配置快照”折叠。明确区分“正在运行”“已完成且已保存”“已完成但历史保存失败”“已取消”。

四种结果视图用横向选择控件显式展示：实验概览、分类统计、按抽次分析、逐抽明细。窄窗口允许换行或退化为紧凑选择，不横向挤压。保留条件分支渲染，不能改成一次执行所有视图的数据查询。

### 3.4 实验概览

第一层为总计口径的六星模拟均值、理论期望、相对误差。相对误差仍按绝对值展示，理论期望为零时不可用。

抽数不再按每轮重复生成行，固定为两行：

| 范围 | 主池抽数 | 赠送抽数 | 总抽数 |
|---|---:|---:|---:|
| 每轮 | D | B | D+B |
| 全实验（T轮） | D×T | B×T | (D+B)×T |

抽数不含假设历史抽数。初始进度仍可查看快照；逐轮具体结果仍从Trace查看。此改动只消除概览的重复展示开销，不承诺加快抽取计算或降低整个模拟的内存上限。

### 3.5 分类统计与并排柱状图

分类选择与来源选择集中在同一工具区域。保持星级、六星构成、六星具体角色、奖励、保底五类及主池／赠送／总计三种来源。

五类图表统一遵守：

- 每个类别为一组两根柱，模拟在左、理论在右，不重叠、不堆叠；横向布局时按相同图例顺序上下并列。
- 图例使用“模拟均值”“理论期望”，颜色对应关系跨图一致，不仅靠颜色辨认。
- 每根柱端显示数值。常规标签统一保留4位小数；非零值若四舍五入会显示为0，则用科学计数法；零值显示明确的0标签。
- 标签格式只影响显示，不修改底层数据。悬停和下方数值表提供更高精度（例如12位有效数字），导出JSON保留原始数值。
- 对相同值、零值和差距极大的值也应分别显示两组标识，预留标签空间，不裁切或互相遮盖。
- 轴标题按类别注明“每轮平均数量／奖励量／触发次数”，明确所选来源。
- 六星角色名称较长或数量较多时采用横向并列柱，增加高度或使用图表区域滚动，不静默省略角色。
- 未配置奖励时显示明确空状态；来源没有六星时，角色占比仍为不可用，不伪装成0概率。

复用现有图表数据转换函数与已安装图表能力；具体绘图库调用在实施时核对现有依赖。历史比较区使用相同展示函数。保留下方数值表，不恢复旧奖励分布页面，也不增加新的统计类别。

### 3.6 按抽次分析

来源、轮次范围、位置范围、计数／比例紧凑分组。图表旁常驻说明：横轴是每轮该来源第几抽，不是保底进度；纵轴为对应星级轮数或频率；比例分母为所选轮次在该位置的实际观察次数。

主池与赠送分别统计，保持默认最多200个位置、单次最多1000个连续位置；可查询第81抽以后。明细的角色或星级筛选不影响此图分母。未开启Trace时解释需要重新运行并保存逐抽明细，不发起明细查询。

### 3.7 逐抽明细

- 第一组为轮次、来源、星级；第二组为角色及可折叠的来源抽次范围。
- 表格上方显示匹配条数、每页条数、基础／完整列。
- 表格下方集中分页和下载，保留50／100／200条、默认100条的设置。
- 保留“准备下载”再“下载明细JSONL”的行为，明确下载全部匹配记录而非当前页。
- 超过网页下载上限则要求缩小筛选，不截断；修改筛选或结果后失效旧下载缓存。

基础列保留轮次、抽次、来源、星级和角色等定位信息；完整列保留概率、保底、奖励等。概率列需明确数值尺度；若实施时采用百分比格式，必须同步标签和文档，底层JSON仍保持0～1。

### 3.8 历史记录

现有历史管理能力继续保留，不视为新增数据库功能：筛选、查看、复用、最多两条汇总比较、单条删除。

筛选在上、历史表居中、针对选择的操作集中。减少每条记录一个完整UUID查看按钮的重复布局，使用同一个选择来源：选一条可查看、复用或删除；选两条可比较，单条操作禁用并提示先选择一条。不新增批量删除。

表格可展示短ID，内部仍按完整UUID操作，完整值在详情可复制，不能按短ID查找或删除。筛选和翻页后清除不在当前页的选择，避免操作错记录。

查看跳转到实验结果；复用跳转到新建实验但不运行。删除与普通操作视觉区分，二次确认时展示目标身份和规模，删除汇总与逐抽数据，清理相关选择和下载缓存，不从任务结果复活。

UI只管理当前v4库中已保存的历史，不管理旧版本数据库、备份文件或未完成任务临时文件。备份恢复仍按现有本地手册操作。

## 4. 真实阶段进度

复用现有后台worker、任务状态和轮询机制，不增加任务服务。按实际工作顺序报告阶段：

| 阶段 | 内容 | 显示方式 |
|---|---|---|
| 等待运行 | 等待worker开始 | 状态文字 |
| 模拟抽取 | 主抽、赠送、统计和Trace分批暂存 | 已完成主抽／总主抽；说明含赠送处理 |
| 理论计算 | 有限期望等对照计算 | 阶段文字；可可靠计数时显示阶段内进度 |
| 明细校验 | Trace数量与序列完整性检查 | 已校验记录／总记录；非Trace跳过 |
| 保存历史 | 导入汇总和Trace | 已处理明细／总明细；无明细时显示保存中 |
| 正在提交 | 最终事务提交和状态发布 | 状态文字，不承诺剩余秒数 |
| 已完成 | 确认计算和保存结果 | 明确成功或保存失败 |

不使用人为加权的全程百分比。计数归属于当前阶段，切换阶段明确重置；100%表示该阶段计数完成，不表示全任务完成。理论计算如包含主池及赠送子过程，可显示子阶段名称，不能伪装成从头倒退的总进度。

理论计算与校验的实际先后以worker实现为准；显示必须跟随真实执行，不能提前切换。进度通知节流，取消检查不依赖UI刷新频率，也不逐抽写状态文件。核心不依赖Streamlit，通过可选回调通知阶段或检查取消，默认不影响原CLI／Python调用。

任务状态仅做本次必要扩展，沿用现有状态模型，不新建数据库表。保持现有主抽计数字段含义，阶段计数如需新增则使用可选字段；现有完成任务缺少新字段时仍可读。历史、结果、Trace、抽样版本不因布局改变而升级；旧进程必须结束后再切换新代码，不要求新旧worker混跑。

## 5. 停止与删除残次数据

### 5.1 用户可见语义

主动停止即放弃整个实验，不保存部分统计，不支持继续运行或从残次数据恢复。

点击停止后显示“已请求停止，正在安全结束当前阶段”，避免重复点击。只有计算退出、事务处理及必要清理完成后才显示取消完成；不能先显示已取消再在后台继续写入。不能承诺所有阶段瞬间停止。

### 5.2 检查位置

抽取、理论递推、Trace校验、历史分批导入均定期检查取消。沿用现有取消异常及批次模式，不复制多套停止机制。理论计算在循环检查点退出；单次不可中断的数据库提交或文件操作需等待其返回。

UI发停止请求，不直接删除worker正在使用的文件。worker自身清理前退出写入循环、关闭连接；外部异常清理必须确认目标worker已经退出或不再写入。

### 5.3 取消与提交的边界

继续用现有任务锁和数据库事务约束最后的取消检查与提交：

- 取消先被接受且未提交：退出计算，回滚历史事务，不保留该次历史。
- 历史提交已经成功：保留完整历史，发布／修正成功状态；稍晚停止请求不删除它，用户可在历史页面单独删除。
- 不能确定进程是否停止或事务是否已提交：保留状态与文件，提示清理未完成；不得猜测后删除或放行冲突任务。

核对已经提交的历史并修正状态属于一致性处理，不是恢复残次实验；不能因“不做恢复”而删除现有的必要保护。

### 5.4 清理范围

仅针对已确认取消且未提交的指定job目录：删除该任务的 `result.json`、Trace暂存库、关闭连接后可清理的伴随文件，以及能确认由该任务创建的未完成临时输出。清除相应结果／下载缓存和取消标记；保留最小取消状态、参数归属信息和日志，供解释任务结局。

不删除整个data或jobs目录，不删除历史数据库及其伴随文件，不触碰其他任务、配置、备份或未知文件。清理失败如实记录，仍不得将其作为完整结果查看；不虚报残次数据已删除。

保留现有异常退出后的归属检查、停止确认、回滚与清理。意外退出的未完成任务不续算；已提交任务的状态一致性检查保留。

### 5.5 保存失败不等于主动取消

本次不增加“重试保存”或其他数据恢复入口，也不顺带删除现有保存失败保护。已经计算完整、但历史保存失败的任务，仍沿用当前汇总／完整暂存保留与当前结果查看规则。只有主动取消且未提交的残次实验按本节作废清理。

## 6. 修改边界与复用

| 现有位置 | 预计职责变化 |
|---|---|
| `dashboard/app.py`、各 `views` | 布局、导航、阶段状态与集中操作 |
| `dashboard/charts.py` | 复用数据投影，统一并排柱和标签所需的数据口径 |
| `dashboard/models.py`、`jobs.py`、`worker.py` | 最小阶段信息扩展、取消协调、终态与清理 |
| `lottery_simulator/engine.py`、`analysis.py` | 可选阶段通知和取消检查，不改变数学／抽样 |
| `dashboard/trace_store.py`、`repository.py` | 校验／保存检查点和阶段内计数，保留原事务保障 |
| 现有测试及操作文档 | 回归、边界和新操作说明 |

上述为职责范围，不要求每个文件必改，也不要求额外创建抽象模块。优先复用现有函数、共享视图、进度和清理入口。

## 7. 验收要求

### 正确性与数据安全

- 固定种子、参数和配置下，改前后抽取结果、汇总统计和Trace顺序一致；进度回调不消费随机数。
- 大轮数概览仍仅两行抽数；顶部轮数、主抽与赠送总量来自当前结果快照。
- 抽取、理论计算、校验、导入均可在检查点取消；取消不留下半份历史或可访问的部分结果。
- 停止前先确认不再写入，覆盖取消／最终提交竞争、重启、清理失败、无法确认提交状态的情形。
- 已成功提交的数据不误删；其他任务、日志、配置和备份不误删。
- 非Trace不创建明细、不进入明细校验；不改变网页上限或本地完整导出行为。

### 图表与交互

- 五类柱状图理论与模拟始终并列，图例、来源、单位正确，零值／相同值／小数／长角色名显示可读数值；图表与数值表一致。
- 轮数醒目，参数草稿切换保留，复用不自动运行；历史选择、比较和删除目标一致。
- 按抽次分析口径不变；Trace分页和下载继续按需查询，下载覆盖匹配记录而非当前页。
- 桌面和窄窗口实际检查无标签挤压、数值裁切；键盘可完成导航、筛选、启动、停止、下载和删除确认，焦点可见。
- 状态不只靠颜色传达；没有Trace、没有奖励、零六星、取消及保存失败均有清楚提示。

测试以相关功能回归和小型端到端实验为主，不添加SHA验证或性能框架。大轮数概览用已有／构造汇总验证，无需为两行表格运行百万次抽样。真实浏览器无法使用时，明确列为未验，不能以组件测试替代视觉结论。

## 8. 实施顺序与交付边界

建议顺序：概览简化与醒目轮数 → 阶段进度及安全停止 → 页面布局和并排数值柱图 → 联合验收及操作文档同步。

设计编写阶段仅新增本文；后续已按用户要求另行编写实施计划，列明代码位置、依赖和功能验收。当前仍只修改文档，保留此前操作文档校对的未提交修改；不实现、不提交、不合并、不推送、不启动服务，也不删除任何历史或任务数据。

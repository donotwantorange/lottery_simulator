# 统一服务器管理菜单设计

- 日期：2026-10-06。用户要求单一脚本选择安装、卸载、运维（启停、备份）和更新；明确卸载提供保留数据或永久删除，永久删除二次确认。
- 基准：master `2612b08`及同工作区尚未提交的[旧镜像预检修复](2026-10-06-upgrade-image-preflight.md)。[计划](2026-10-06-server-management-plan.md) · [实施记录](2026-10-06-server-management.md)。

## 入口与复用

无参数 `scripts/install.sh`显示一级菜单；原首次安装流程改为显式 `--install`，原已下载版本升级保留 `--upgrade`。新增source的manage.sh承载菜单及管理函数。复用原前后端构建、网络预检、备份接口、旧任务检查脚本及systemd示例；无新依赖或业务改动。

菜单Git更新核对目录、master、干净工作区及预期origin，确认后 `git pull --ff-only origin master`，再exec新版脚本升级，避免边执行旧函数边读取新脚本。ZIP支持只更新已下载版本；不自动丢弃修改、强推或回滚。

## 服务与数据范围

只管理同机标准Docker的本目录app/Caddy，核对容器标签、实际v5/v6路径及命名卷，不依据新版Compose猜旧库。状态和日志只读；启停/重启操作原ID，不重建旧app。暂停的app恢复需要独立确认；停止前操作者结束任务、停止新提交及在途请求，脚本暂停timer、停止Caddy并用旧容器验证器拒绝活动/未知状态，给app120秒停止期限。不提供强制终止活动实验的入口。

手动备份识别实际数据库版本，在线SQLite快照输出到原备份卷和仅管理员访问的私有目录，不把容器路径当宿主机路径。每日备份自动安装/更新限制标准目录、默认项目名、Docker路径，拒绝其它unit路径、drop-in及其它service目标，备份已有unit，实际备份成功后才启用timer；操作者确认业务/HTTPS验收，不拿启动当验收。

保留数据卸载先确认旧镜像可创建无数据卷容器、保存旧容器及环境元数据，只移除原服务和本项目网络，保留四个持久卷及.env；timer停用，unit定义保留。v6可从安装子菜单重装：原卷齐全且无使用者，检查v6数据与任务并生成快照，随后migrate和启动，不初始化账号。v5保留库按明确账号迁移流程处理，不自动猜测旧业务恢复方案。

永久删除需 `UNINSTALL`及 `DELETE-<项目名>`两次输入，先展示并验证四个卷、固定私有备份树和.env；拒绝其它容器占用、网络非本项目、备份路径重定向。删除前再次核对备份路径。代码、Docker、其它项目、外部及异机备份保留，不承诺整盘擦除。容器列表读取失败不是空列表，必须退出。

## 验证与边界

沿用现有unittest/PTY假Docker/systemctl/Git测试，不对真实库、生产unit或项目执行删除；永久删除的正例文件操作只在临时项目中模拟，实际删除函数额外验证越界路径拒绝。保留此前真实SQLite检查；Shell语法、原首次安装/升级和文档链接一并检查。

完整新服务器安装、真实升级、生产备份调度/恢复、真实卸载与可信公网HTTPS需要实机证据。本轮不连接服务器、不提交或推送、不修改原本地使用手册。

# 开发与验证规范

来源：用户在本项目会话中提供的通用AGENTS指令，以及[既有验收安排](../changes/2026-09-30-independent-rules-rarities-design.md#14-实施与验收原则)。本文件将这些要求落到仓库，原AGENTS指令并非仓库已有文件。

2026-10-08按用户最新要求明确：减少不必要验证，同一功能的相关修改集中验收；原先一律隔离回退的表述调整为因果不明确时才增加对照验证。

范围：诊断、验证与证据方法的主要维护位置；文档阶段、记录格式及Git状态填写方式见[变更记录规范](change-records.md)，专题规范仅补充各领域的验收场景。

## 核心原则

改了代码不等于修了问题；验证过对应行为，才可以说明修复生效。

验证与改动风险、影响范围相称，以确认实际功能为目标。默认流程为“连续完成一组相关修改→验证受影响功能→有明确风险再补充回归→通过后结束”，不要求每改一个字段、函数或文件都单独验证。

按请求类型执行：审查和诊断先提供证据，文档整理只改文档，实施按已确认范围推进。保留用户已有修改，不将规范整理当作业务重构或操作真实数据的授权。

## 诊断与因果验证

- 需要实验诊断时按成本排序，选择禁用可疑组件、最小化系统或替换已知正确实现等适用手段，不机械执行全部方法。
- 修复先确认原问题，再验证修改后的行为。可稳定复现的问题，通常“修复前失败→修复后通过”已足够；已有可信复现证据可复用，不重复搭建相同现场。
- 仅当因果关系不明确、问题不稳定、时序/缓存/加载路径有疑点或多个因素同时变化时，增加隔离回退、禁用或其他对照实验。选择能回答疑点的最低成本方式，不把回退列为每项修复的必做步骤；回退不得影响用户工作或真实数据。
- 连续两个修复无效时，回到第一个修复核对前提，不继续扩大猜测。
- 排除原因前需确认干预确实生效，并有正面实验依据；现象不变本身不足以排除。
- 区分根因修复与提高容错能力，不能用后者冒充前者。

## 验证范围

- 同一功能中的相关修改可以连续完成；中途只做排除实施阻塞、确认高风险前提所需的检查，完整流程连通后集中验收。互不相关的功能按各自影响范围处理，不为了集中验收而积累未解决的失败。
- 优先复用已有测试或最小操作用例。可逆、低风险修改不强制新增自动化测试；确需补用例时验证行为和重要边界，不编写只复述实现的测试。
- 不做不必要的SHA核对，不逐步骤、逐文件或逐子任务重复全套测试。同一场景已有充分证据时，不机械叠加单元、接口、浏览器三套相同验证；只有不同层的未覆盖风险才需要追加。
- 测试、失败注入、删除和迁移演练使用明确的隔离目录/数据库/资源；不得默认连接真实数据路径。

| 改动类型 | 默认验证范围 |
| --- | --- |
| 文档、注释、提示文字 | 核对改动内容和差异；仅在修改链接、路径或标题时检查相关引用，不重新扫描所有文档，不运行业务测试 |
| 局部界面调整 | 检查受影响页面和适用状态；涉及布局才补相关尺寸/缩放检查，不重验无关业务 |
| 一组关联功能修改 | 连贯完成后集中验证完整功能流程，选择有意义的边界和状态转换 |
| 概率、权限、保存、删除等关键逻辑 | 验证受影响关键边界及必要回归；真实数据操作前的保护检查仍保留 |
| 大范围集成或发布 | 根据影响面和约定交付范围决定是否运行全套、构建或部署验收，不自动把所有层级全部执行一遍 |

专题验收清单是按影响面选取的场景集合，不是每次修改的必跑列表。浏览器验收、产物核对或部署演练只在本次涉及对应内容时执行；具体功能验收不能被无关检查数量替代。

## 停止条件

相关功能和本次必要回归通过，没有新增异常或未解决疑点后，即结束验证。不为了“更保险”继续扩大范围、补截图、重跑同一用例或增加报告。

后续发生新改动、失败或具体疑点时，仅补查受影响部分；一次失败后修正并通过，通常不需要重跑所有无关模块。确实无法完成的必要检查应说明范围和原因，不虚报通过，也不以无限增加替代检查掩盖缺口。

## 实际运行产物

编译完成不代表运行的就是新产物。对本次需要运行验收的.so、dll、二进制或网页构建，确认实际加载路径；存在多份产物时核对路径、时间和运行环境。版本及加载路径未变且已经确认时不反复核对，不以源码修改或构建成功代替必要的运行验证。

## 结论与证据

- 结论使用“✅已验证／⚠️推断中／❓假设”区分证据强度；静态核对明确标为静态核对，不能冒充动态复现。
- 量测说明环境、范围及盲区；优化说明消除了什么开销、不能解决什么问题，不将局部结论推广到全局。
- 明确区分已设计、已实现、已验证、已合并、已推送和已部署。旧环境、单元测试或本地HTTPS成功不能证明服务器整套流程通过。
- 记录与改动规模相称：小修改简述改动、确认方式和结果即可；相关命令及未验事项按需补充，不强制完整日志归档、截图矩阵或独立测试报告。复杂迁移、难复现故障或用户要求时再保留必要的详细证据。
- 避免暴露密码、密钥、会话或账号私密材料；不编造测试或提交记录。

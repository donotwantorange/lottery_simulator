# 架构与数据规范

来源：[独立规则与通用稀有度设计](../changes/2026-09-30-independent-rules-rarities-design.md)、[任务可靠性设计](../changes/2026-10-02-v6-runtime-reliability-fixes-design.md)。本文件记录已选架构的长期约束，具体算法和版本仍见业务设计与代码。

范围：计算与数据一致性的主要维护位置。账号和资源授权见[权限规范](permissions.md)，数值与快照的页面表现见[界面规范](ui-interaction.md)，真实数据的备份与切换操作见[部署规范](deployment-safety.md)。

## 职责与引用

- Python核心负责概率、抽样、状态、模拟与理论；Django服务负责权限、资源、任务和持久化；React负责交互及结果展示。
- 规则决定怎么抽；池绑定一条规则并定义角色、权重、奖励和目标；实验引用池及运行参数。实验不能绕过池另行覆盖规则。
- 网页对象存数据库，配置文件用于默认示例和CLI输入，不自动双向同步。CLI离线运行不自动写入网页历史。
- 规则是经过校验的数据，不是用户上传的可执行代码。稀有度、角色、奖励用稳定ID关联，名称不参与身份或概率判断。

## 概率与复现

- 概率计算不消耗随机数；统一执行器执行抽样；状态推进和额外事件职责独立。
- 模拟与理论共用概率、目标解析和状态转移含义。理论递推不用随机抽样替代理论值，等待分析和有限实验期望采用适合各自问题的算法。
- 有限、非负、归一化的概率向量及数值边界统一处理；允许的浮点尾差不能让模拟和理论使用不同的分布。
- 复现依赖配置、参数、实际种子、抽样版本及受支持环境。结果记录RNG和环境信息；Trace开关、进度回调、记录批次和界面动画不改变核心随机数消耗。
- 抽样顺序或算法语义改变时检查并更新相应版本及复现说明，不能把新结果声称为旧算法的原样复现。

## 接受任务与历史

- 接受任务时核对池和规则修订，冻结规则、池、解析目标、参数、种子及必要版本信息；已接受任务不重新读取可变配置来改变规则。
- 当前配置更改影响之后接受的任务；历史读取保存的快照。按当前池重跑生成新任务，不能覆盖原历史或冒充原样重放。
- 抽取、赠送池抽取、直接赠送及角色获得合计分开统计。事件数不等于角色数量，历史累计不等于本次抽数；各页面、图表、导出使用同一口径。
- Trace关闭只保存参数、快照和汇总；开启才记录过程事件，不能事后补造随机明细。大量明细分页读取、分批保存和流式下载。

## 持久化、版本和输入

- 数据库schema由Django migrations唯一管理，仓库层不暗中建表；文件改名或手工改版本号不能代替迁移。
- 不兼容数据库、任务、事件和结果必须明确拒绝或隔离；格式变更同时检查任务目录、状态引用和导出，不能只换数据库文件。
- 格式、修订、抽样版本使用约定整数并拒绝bool，算法版本遵守其字符串契约；具体当前版本号在代码中维护。
- 类型、范围、引用和可序列化边界必须在服务端检查。创建、编辑、导入及CLI遵循各自明确契约，共用语义不能出现入口绕过；非法输入应有可理解的参数错误。
- 大整数跨浏览器传递遵守精确十进制契约，不经浮点数中转；概率与奖励拒绝非有限数值，溢出不能变成有效结果。
- 临时事件校验完成后，汇总和全部事件原子保存；索引列与事件JSON保持一致，不提交半份历史。

## 任务、取消与失败

- 当前采用全站单活动模拟任务，准入与取消/提交边界由共享锁和事务协调，不能由浏览器状态代替。
- 提交响应丢失时查询本人任务，不自动重放任务创建。取消、保存和完成状态依据实际后台进度，模拟结束不等于全部结束。
- 未确认或损坏的任务状态不能当作无任务并清空；已提交历史与终态恢复不重新模拟。失败时区分临时结果清理与已保存历史，不删除已成功提交的数据。
- 扩展队列、多机运行或更换存储时，必须重新设计这些一致性边界，不能仅放开前端限制。

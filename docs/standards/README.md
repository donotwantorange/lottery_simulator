## 规范、设计与说明的分工

- 本目录说明“长期应遵守什么”，不记录某轮任务进度或当前在线状态。
- [修改记录目录](../changes/README.md)保留“为什么改、这次改什么、如何实施、实际验证和合并结果”。设计引用规范，不重复维护全部规范正文。
- [网页指南](../dashboard-guide.md)、[部署指南](../deployment.md)等操作文档说明已实现功能怎么用；不能提前把待实施要求写成可执行步骤。
- 当前概率、保底阈值、版本号、数据库路径、默认配置等具体值仍以对应配置、代码和当前业务设计为准，不固化成不可变的开发规定。

## 生效与维护

本目录是既有约定的集中整理，不是新功能已完成的声明。开发验证要求来自用户提供的通用AGENTS指令及项目验证安排；其他规范来自已确认的设计。历史记录里的“已通过”只代表当时列明的范围。

用户最新明确决定优先；只有被明确确认且改变相应约定的新设计才可调整规范，未实施代码或未确认提议不能悄悄改变规范。发现相互冲突时，核对决定来源，明确本次采用的要求并同步规范与引用；不以“文档日期更新”自动覆盖全部历史决定。

每条长期要求只在本目录对应文件维护；历史设计作为来源保留，不批量改写旧结论。若规范变更伴随代码改动，在对应变更记录说明；纯文字整理不额外创建代码变更记录。

规范不授权执行提交、推送、部署或删除。是否完成某项工作，以实现与证据为准。
